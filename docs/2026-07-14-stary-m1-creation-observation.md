# STARY M1 创造与观测实施计划

## 目标

在 M0 物理和观测底座上，交付可选择的恒星系统场景、通用天体目录、多天体观测、天体创建、参数编辑和短期轨道预览。

本文件是 M1 的独立实施骨架。每项任务开始前仍要检查实际代码、数据来源和上一项验证结果，再确定最终文件和提交边界。

## 范围

### 包含

- 太阳系主要天体模板，以及空白、双星、随机系统的模板边界。
- 通用天体元数据、父子层级和稳定标识。
- 多天体画面、轨道父体、选择、定位、跟随和相机观察。
- 六类天体的创建草稿、位置与速度输入。
- 质量、半径、位置和速度等物理参数编辑。
- 一次性短期试算、轨迹预览、碰撞和逃逸风险提示。
- 确认创建、编辑和删除后的正式物理线程更新。

### 暂缓

- 高级行星表面、大气、云、体积光和完整尺度切换，这些进入 M2。
- 分层碰撞、主要碎块和视觉碎屑，这些进入 M3。
- 历史分支、倒退、存档和导入导出，这些进入 M4。
- 512 天体和 50,000 视觉碎屑的最终性能承诺，这些进入 M5。

## 已有基础

- REBOUND/IAS15 已能从 1 到 512 个 SI 天体初始化并输出守恒诊断。
- Worker 协议具备版本、会话、序号、运行时校验和错误暂停。
- 观测台能按天体数组创建、更新和移除画面对象。
- 当前正式协议只含 `initialize`、`start`、`pause`、`step`、`setTimeScale` 和 `dispose`。
- M0 验收基线记录在 `docs/2026-07-14-stary-m0-acceptance.md`。

## 当前进度

- Task 1 已完成：JPL J2000 太阳系 10 体模板、质心化和 REBOUND 一儒略年验证。
- Task 2 已完成：通用目录、月球父级轨道、全景与聚焦跟随、定位点避让和多天体浏览器验收。
- Task 3 等待公共协议方案确认。

## 执行任务

### Task 1：建立场景与太阳系主要天体

- 建立物理常量、场景定义和应用展示元数据的边界。
- 加入太阳、八大行星和月球，记录公开数据来源、历元和换算方法。
- 把初始状态转换到质心参考系，验证确定性、有限数、唯一 ID、总动量和短期稳定性。

### Task 2：交付通用目录和多天体观察

- 删除太阳地球专用名称、类型、颜色和无障碍文案。
- 按恒星、行星和卫星父子关系展示目录。
- 轨道以声明的父天体为参考，月球轨道围绕地球。
- 增加选中天体定位、跟随和拥挤标记布局。

### Task 3：确定运行时天体修改协议

- 设计新增、编辑、删除命令、确认响应和失败回滚。
- 规定修改时的暂停要求、序号语义、守恒基线重建和模拟时间连续性。
- 评估协议版本升级与整场景重建方案。

该任务会改变公共消息结构。实现前按仓库规范请用户确认最终方案。

### Task 4：交付创建草稿和轨道预览

- 创建草稿与正式模拟隔离。
- 支持选择天体类型、确定位置和拖出初速度向量。
- 使用独立短期试算返回轨迹点、碰撞和逃逸风险。
- 用户确认后再写入正式模拟。

### Task 5：交付参数编辑和删除

- 提供带单位的数值输入、边界说明和错误反馈。
- 编辑或删除以原子操作提交，失败时保留原状态。
- 处理选中项删除、目录更新、轨道刷新和守恒基线变化。

### Task 6：M1 收口

- 完成核心纯函数、协议、REBOUND 集成和浏览器流程测试。
- 记录多天体性能、包体变化和已知限制。
- 更新路线图及场景、物理、画面、创造工具模块文档。

## 验收重点

- 太阳系模板可重复生成，数据来源与历元可追溯。
- 太阳、八大行星和月球都能显示、选择和查看 SI 数据。
- 月球轨道父体正确，拥挤天体标记可区分。
- 创建草稿不会提前改变正式模拟。
- 非法数值、重复 ID、数量上限和错误会话均被拒绝。
- 短期预览不会阻塞画面，取消预览会释放 Worker 和 WASM 资源。
- WebGPU 与 WebGL2 都能完成场景选择、创建和编辑流程。
- 桌面与手机关键流程通过真实浏览器验收。
