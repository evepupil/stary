# STARY M1 创造与观测实施计划

## 目标

在 M0 物理和观测底座上，交付可选择的恒星系统场景、通用天体目录、多天体观测、天体创建、参数编辑和短期轨道预览。

本文件是 M1 的独立实施骨架。每项任务开始前仍要检查实际代码、数据来源和上一项验证结果，再确定最终文件和提交边界。

## 范围

### 包含

- 太阳系主要天体模板，以及空白、双星、随机系统的模板边界。
- 通用天体元数据、父子层级和稳定标识。
- 多天体画面、轨道父体、选择、定位、跟随和相机观察。
- 六类天体的创建草稿、位置与速度输入。
- 质量、半径、位置和速度等物理参数编辑。
- 一次性短期试算、轨迹预览、碰撞和逃逸风险提示。
- 确认创建、编辑和删除后的正式物理线程更新。

### 暂缓

- 高级行星表面、大气、云、体积光和完整尺度切换，这些进入 M2。
- 分层碰撞、主要碎块和视觉碎屑，这些进入 M3。
- 历史分支、倒退、存档和导入导出，这些进入 M4。
- 512 天体和 50,000 视觉碎屑的最终性能承诺，这些进入 M5。

## 已有基础

- REBOUND/IAS15 已能从 1 到 512 个 SI 天体初始化并输出守恒诊断。
- Worker 协议具备版本、会话、序号、运行时校验和错误暂停。
- 观测台能按天体数组创建、更新和移除画面对象。
- 当前正式协议为 v2，在初始化、时间控制和销毁命令之外，已经支持完整快照形式的 `replaceBodies`。
- M0 验收基线记录在 `docs/2026-07-14-stary-m0-acceptance.md`。

## 执行任务

### Task 1：建立场景与太阳系主要天体

- 建立物理常量、场景定义和应用展示元数据的边界。
- 加入太阳、八大行星和月球，记录公开数据来源、历元和换算方法。
- 把初始状态转换到质心参考系，验证确定性、有限数、唯一 ID、总动量和短期稳定性。

### Task 2：交付通用目录和多天体观察

- 删除太阳地球专用名称、类型、颜色和无障碍文案。
- 按恒星、行星和卫星父子关系展示目录。
- 轨道以声明的父天体为参考，月球轨道围绕地球。
- 增加选中天体定位、跟随和拥挤标记布局。

### Task 3：确定运行时天体修改协议

- 已把公共协议升级为 v2。新增、编辑和删除统一提交完整 `replaceBodies` 快照，成功返回 `bodiesReplaced` 真实物理快照。
- controller 自动等待暂停后再提交；Worker 仍会拒绝任何运行中的直接替换命令。
- `bodyRevision` 只在成功替换后递增。草稿在创建时同时记录预期修订号和天体快照时间，提交时显式传入；任一值过期都会明确冲突。消息 `sequence` 继续表示同一会话内的发送顺序，错误响应通过 `requestSequence` 关联触发命令。
- 候选 REBOUND 实例先创建并读取首帧，成功后再切换；失败时销毁候选并保留旧实例。
- 新实例以当前模拟时间作为时间原点，确认响应保持时间连续并重建守恒基线。

协议方案已经用户确认并完成实现。Task 4 和 Task 5 直接复用该原子替换入口。

### Task 4：交付创建草稿和轨道预览

- 已把创建草稿与正式模拟隔离。打开工具后先暂停，并等待天体快照时间追上显示时间，再冻结 bodies、修订号和快照时间。
- 已支持恒星、岩石行星、气态行星、卫星、黑洞和小行星群；小行星群生成 6 个独立粒子。
- 已支持在 `z=0` 轨道平面按下确定位置、拖动生成真实 SI 初速度，画面显示草稿球和速度箭头。
- 已增加独立版本化预览 Worker，使用 REBOUND/IAS15 返回 256 个展示点，并在展示点之间执行最多 4096 个风险采样，提供碰撞和二体能量逃逸风险。
- 已恢复预览的输入惯性坐标系，严格校验响应轨迹与原请求的对应关系；大质量恒星和黑洞的轨迹首点与草稿位置一致。
- 已保存进入创造模式前的相机，创建期间切到稳定俯视构图；恒星按类型发光，黑洞保持非发光。
- 已在用户确认后通过冻结修订号和快照时间调用 `replaceBodies`。取消会释放草稿和预览；确认后保持暂停并聚焦新天体。

### Task 5：交付参数编辑和删除

- 已提供带单位的质量、半径、三维位置和三维速度输入。界面使用 `kg`、`km`、`AU` 和 `km/s`，确认前严格解析并换算成 SI；空值、非有限数字、非正质量和负半径都有字段级错误。
- 已在有效字段变化后等待 250ms 再启动一次性 REBOUND 预览。新输入会取消旧定时器和旧 Worker，只有当前编辑修订的结果可以进入画面。
- 已通过同一个 `replaceBodies` 原子入口提交编辑和删除。编辑保留天体 ID；删除拒绝不存在、重复或最后一个天体。
- 已把修订与快照时间冲突显示为独立状态。用户需要明确点击重同步，工具才会读取最新正式快照并重新试算，旧草稿不会直接覆盖新状态。
- 已在删除后优先选择仍存在的目录父体；父体已删除时按当前位置的引力优势选择，再回退到首个合理天体。轨道父体解析也会在声明父体消失后执行同样的引力回退。
- 已让编辑预览支持 `referenceBodyId=null`。此时仍计算轨迹和碰撞风险，只跳过需要参考天体的逃逸判断。
- 编辑沿用用户当前相机构图，创建继续使用俯视相机；两个工具互斥，任一工具活动时都不能进入另一个工具。

### Task 6：M1 收口

- 已审计核心纯函数、协议、REBOUND 集成和浏览器流程覆盖，并补充 WebGL2 编辑冲突恢复与预览中取消清理流程。
- 已记录默认 10 体场景的两秒 WebGPU 性能、生产包相对 M0 的变化和 M1 已知限制。
- 已更新路线图及场景、物理、画面、创造工具模块文档。完整证据见 `docs/2026-07-15-stary-m1-acceptance.md`。

## 验收重点

- 太阳系模板可重复生成，数据来源与历元可追溯。
- 太阳、八大行星和月球都能显示、选择和查看 SI 数据。
- 月球轨道父体正确，拥挤天体标记可区分。
- 创建草稿不会提前改变正式模拟。
- 非法数值、重复 ID、数量上限和错误会话均被拒绝。
- 短期预览不会阻塞画面，取消预览会释放 Worker 和 WASM 资源。
- WebGPU 与 WebGL2 都能加载太阳系场景并完成创建、编辑或删除关键流程。
- 桌面与手机关键流程通过真实浏览器验收。

以上验收重点均已通过。空白、双星和随机系统在 M1 只确定模板边界，场景选择入口留给后续产品任务。
