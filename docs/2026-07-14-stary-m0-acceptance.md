# STARY M0 验收记录

## 结论

M0 工程底座与双天体垂直切片通过验收，可以进入 M1 创造与观测阶段。

本记录以提交 `ff91975` 为功能基线，并在临时 detached worktree 中加入只读性能探针后采样。这样可以避免后续太阳系开发改变 M0 的包体和运行频率。临时 worktree 和预览服务均在验收后清理。

## 生产构建

命令：`pnpm build`

| 项目                 |  原始字节 | gzip 字节 |
| -------------------- | --------: | --------: |

| REBOUND WASM         |   233,850 |    92,608 |

构建没有 source map，只有一个正式 Physics Worker 和一个 REBOUND WASM。WebGPU、WebGL2 和观测场景保持动态分块。

Vite 会提示 REBOUND Emscripten 胶水中的 `node:module` 已为浏览器外部化。该提示没有阻止构建，浏览器 Worker、WASM 加载、WebGPU 和 WebGL2 回退均通过真实验收。页面控制台没有 warning 或 error。

## 两秒性能样本

当时的采样命令：`pnpm test:performance`。该探针临时加入 `ff91975` detached worktree 后运行；主分支上的同名命令始终测当前默认场景，当前十体结果不能覆盖这份历史基线。

探针等待模拟进入运行状态并收到首个 Worker state，然后连续采样至少 2,000 毫秒。RAF 指浏览器画面刷新回调；Worker state 频率根据相邻 state 消息的单调序号差计算，采样期间不发送控制命令。

| 指标                  |        结果 |
| --------------------- | ----------: |
| 实际采样时长          | 2,007.10 ms |
| RAF 回调数            |         121 |
| RAF 频率              | 60.29 次/秒 |
| Worker state 序号推进 |          67 |
| Worker state 频率     | 33.38 次/秒 |

该结果用于 M0 双天体基线和后续回归对照。它不代表 512 个主要天体、50,000 个视觉碎屑或低性能设备的首版承诺，这些规模验收仍由后续里程碑负责。

## 门禁

在纯 M0 临时 worktree 运行 `pnpm check`，结果如下：

- 格式检查通过。
- ESLint 零错误、零 warning。
- TypeScript strict 类型检查通过。
- Vitest 12 个测试文件、94 项测试全部通过。
- 生产构建和产物锁检查通过。
- Playwright 4 个流程全部通过：性能样本、桌面观测与时间控制、手机抽屉、WebGL2 回退。
- 应用内浏览器验证页面标题、非空画布、WebGPU 后端、暂停交互和控制台健康；画布尺寸为 `1920 x 911`，控制台 warning/error 为 0。

## M0 已知限制

- 功能基线只包含太阳和地球，完整太阳系模板进入 M1。
- 正式物理协议只支持初始化和时间控制，运行时天体增删改进入 M1。
- 天体名称、类型和颜色仍有太阳地球专用映射，通用目录进入 M1。
- M0 轨道展示以最大质量天体为中心，卫星父子轨道进入 M1。
- 高级表面、大气、尺度切换和画质分档进入 M2 及后续里程碑。
- 本次性能数据只覆盖参考机器上的双天体场景。

## 进入 M1 的门槛

- 工具链可重复安装、构建和测试。
- REBOUND/WASM 构建输入和产物已锁定。
- SI 数据、跨线程校验、顺序门和错误暂停已建立。
- 双天体物理、渲染、时间控制、手机布局和 WebGL2 回退已完成真实验收。
- 当前限制都有明确后续归属。

以上条件全部满足。M1 可以开始，实施骨架见 `docs/2026-07-14-stary-m1-creation-observation.md`。
