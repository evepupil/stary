# STARY M2 真实画面实施计划

## 目标

在 M1 已通过验收的太阳系观测、创建和编辑能力上，建立可审计、可降级、可持续扩展的真实画面管线。M2 要让恒星、岩石行星、气态行星、行星环、大气、云层、光照和黑洞拥有与类别相符的外观，并让远景、轨道区和近景之间的观察保持稳定。

物理状态继续是唯一事实来源。材质、纹理、光照、细节层级和视觉增强只影响画面，不得修改质量、半径、位置、速度、时间或碰撞结果。

本文件是 M2 的实施骨架。Task 2 已完成，下一步进入大气、云层、光照与曝光。

## 范围

### 包含

- 建立渲染资源、材质、纹理、灯光、细节层级和质量配置的明确职责边界。
- 为真实太阳系优先使用可追溯的 NASA 或其他公共数据，并记录来源、许可、处理方式和固定输入。
- 为用户创建的恒星、岩石行星、气态行星、卫星、黑洞和小行星提供确定性外观回退。
- 恒星颜色与亮度、岩石与冰质表面、气态行星云带、行星环、大气、云层、阴影和高动态范围曝光。
- 多恒星照明、日食和月食所需的光照与遮挡基础。
- 远景、轨道区和近景的细节层级、相机速度、坐标稳定性和尺度切换。
- 黑洞的可观察外观、背景扭曲边界和无吸积物质时的明确回退。
- WebGPU 优先与 WebGL2 功能回退，桌面与手机关键观察流程保持可用。
- 实际场景帧、天体区域像素、资源计数、包体和性能的自动化证据。

### 暂缓

- 分层碰撞、熔融、喷射、主要碎块和视觉碎屑进入 M3。
- 撤销、历史、存档、导入导出和实验回放进入 M4。
- 512 个主要天体、50,000 个视觉碎屑、完整设备分档和低性能设备最终承诺进入 M5。
- 完整广义相对论、黑洞内部和恒星完整生命周期不在首版范围。
- 黑洞背景扭曲属于画面近似，不改变 M1 的牛顿引力模型。
- 跨浏览器只承诺视觉与数值容差内一致，不承诺逐像素或逐位相同。

## 已有基础

- Three.js 场景已经支持 WebGPU 优先、WebGL2 回退、动态分块和明确的 renderer 清理。
- 默认场景为 JPL J2000 太阳系 10 体，天体目录提供类别、颜色、轨道父级和稳定 ID。
- 天体 sphere 使用真实物理半径，定位环、轨道和星空与正式 mesh 分层绘制。
- 场景已经区分 `star`、`solid` 和 `black-hole`，恒星提供点光源，黑洞保持非发光。
- 全景、聚焦跟随、相机环绕、桌面与手机布局、创建和编辑草稿覆盖层已经通过 M1 验收。
- Playwright 已覆盖非空画布、选中轨道、定位环、相机状态、WebGPU、WebGL2 和关键交互。
- M1 参考机最终样本为 2,008.60 ms 内 121 次页面 RAF 和 67 次 Worker state 推进；该数据只作为 M2 回归对照。

## 当前进度

- Task 1 已完成：六类确定性外观、恒星质量/半径到光度和色温、最多四个恒星灯光、跨后端材质资源、三档尺度与 LOD、场景重标定和低频视觉诊断。
- Task 2 已完成：固定 Solar System Scope / INOVE 的 CC BY 4.0 本地资产，交付 10 个太阳系天体表面、土星实体环、资源缓存、取消、回退和双后端浏览器证据。
- Task 3 下一步开始：交付独立大气、云层、阴影与曝光适应。

## 执行任务

### Task 1：建立真实画面基线与诊断

状态：已完成。

- 已把外观、尺度和 Three.js 资源拆到独立模块，`observatory-scene.ts` 只编排状态、相机、轨道和诊断。
- 已按恒星、岩石、气态巨行星、冰巨行星、无气层和黑洞建立确定性外观；动态恒星按质量和半径估算主序星光度、温度和 sRGB 颜色。
- 已把恒星表面变化、柔和光晕和点光源作为独立资源管理。LOD 变化只替换并释放 geometry；单体删除和场景销毁会释放完整 geometry、material、texture 和 light。
- 已把活跃恒星灯光硬限制为最多四个，按质量和稳定 ID 选择；更多恒星仍保持自发光外观。
- 已用平方距离衰减和固定 30 AU 显示基准补偿场景缩放，远处新增天体不会改变原有恒星与行星的照度。
- 已建立 `system`、`orbit`、`surface` 三档尺度和 `low`、`medium`、`high` 三档球体 LOD，阈值带滞回，WebGL2 使用较低分段。
- 已修复同一批 ID 被大幅移动或缩小时场景比例不更新的问题；物理范围扩大超过 5% 或缩小超过 50% 时重新标定。
- 已在聚焦天体本身清楚可见时收起定位环，避免近景标记遮住表面。
- 已新增仅在 `visualDiagnostics=1` 下启用的低频诊断，包含实际场景帧、尺度档、材质类别、LOD 数量、活跃灯光、曝光、聚焦标记状态和天体投影区域。
- 已通过桌面默认后端和手机 WebGL2 的真实画布、实际场景帧、外观分类、LOD、太阳近景球面/光晕与 console 验收。

Task 1 完整 `pnpm check` 通过 35 个 Vitest 文件、275 项测试和 17 条 Playwright 流程。生产包为 `1,953,885` 原始字节、`560,709` gzip 字节，相对 M1 增加 `12,400` 原始字节和 `3,907` gzip 字节。完整门禁中的单次两秒 WebGPU 样本为 `55.98` RAF/秒、`32.99` Worker state/秒；它只作为回归观察，M2 重复性能基线仍由 Task 5 统一记录。

### Task 2：交付恒星、行星表面与行星环

状态：已完成。

- 已固定 Solar System Scope / INOVE 资产来源、CC BY 4.0 许可、原图与成品 SHA-256、处理工具和尺寸；运行时只读取仓库本地文件。
- 已把太阳、八大行星和月球表面转成 `1024×512` WebP，把土星环转成 `1024×63` PNG；11 个成品合计 `550,977` 字节。
- 已建立严格运行时清单、HTTP 与 MIME 校验、ImageBitmap 解码和 Three Texture 独立释放。
- 已建立场景级纹理缓存，共享请求、引用计数、单等待方取消、全体取消、失败条目淘汰、迟到资源释放和幂等销毁均有单测。
- 固定太阳系天体在聚焦或进入 medium LOD 时按需加载表面；用户创建和未知天体继续使用确定性程序化外观。
- 土星实体环使用 `1.24R..2.27R` 半径与 `26.73°` 轴倾角，径向 UV 驱动透明度条带；加载失败时保留程序化环带。
- 固定天体聚焦进入真实半径近景，构图留出 `2.1R`；土星按完整外环扩展画幅。全景入口、轨道线和相机环绕继续可用。
- 已增加表面、行星环、缓存和环投影诊断；桌面默认后端与手机强制 WebGL2 均验证地球海陆纹理、土星左右环带、内洞和径向结构。
- 地球资产返回错误 MIME 时继续显示可选择、可聚焦的程序化球面。单次资产失败在当前场景保持稳定回退，页面重建后重新加载。

Task 2 完整门禁通过 39 个 Vitest 文件、291 项测试和 18 条 Playwright 流程。生产包为 `2,521,163` 原始字节、`1,117,354` gzip 字节，相对 Task 1 增加 `567,278` 原始字节和 `556,645` gzip 字节。大部分增量来自 11 个本地画面资产；正式 5 秒性能矩阵仍由 Task 5 统一记录。

### Task 3：交付大气、云层、光照与曝光

- 大气边缘厚度和颜色随视角变化，不能把整个行星覆盖成单色球。
- 云层具有独立高度、移动与阴影，并能按质量档位降级或关闭。
- 多恒星场景最多由四颗质量最大的恒星提供实时照明，其余恒星保留自发光表面与光晕；行星、卫星和黑洞不得误发光。
- 建立日食、月食和行星环阴影的遮挡基础。
- 高动态范围曝光支持从恒星到暗面观察的平滑适应，并保持 UI 可读。

### Task 4：交付尺度切换与黑洞画面

- 沿用已有 `system`、`orbit`、`surface` 三档尺度，补齐切换时的相机速度、选择、聚焦和方向连续性。
- 根据已有观察尺度调整 near/far、原点重定位和实际近景资源，避免穿模、闪烁和远离原点后的抖动。
- 真实观测和增强观测共用同一份物理状态，视觉开关不得改变 Worker 状态或守恒诊断。
- 黑洞提供与普通实体不同的可观察轮廓；背景扭曲和吸积盘按能力降级，WebGL2 必须保留明确可辨识回退。

### Task 5：M2 兼容、性能与文档收口

- 完成核心纯函数、渲染资源、双后端和浏览器流程测试。
- 在同一参考环境用预热后连续 5 秒、至少三次的正式矩阵，记录全景与代表天体近景的实际场景帧、页面 RAF、Worker state、资源存活数和生产包变化。
- 重复全景/聚焦、质量切换、创建/取消、编辑/取消和视口重建，确认资源数量达到稳定平台后不再增长。
- 完成桌面与手机截图审查，覆盖布局、文字、遮挡、近景构图和后端回退。
- 更新路线图、验收记录和相关模块设计归档，明确 M3 与 M5 的后续边界。

## 验收重点

### 视觉与交互

- 自动化从天体诊断提供的投影中心和屏幕半径取样，避免依赖固定坐标。
- 恒星、岩石行星、气态行星、行星环、大气和黑洞各有至少一个代表场景证据。
- 非空画布、轨道、定位环、目录选择、全景、聚焦和时间控制不得回归。
- WebGPU 与 WebGL2 比较视觉组成和宽容范围，不要求逐像素一致。
- 桌面至少覆盖 `1440x900` 和 `1280x720`；手机至少覆盖 `390x844`。
- 纯外观不写单元测试，使用画布像素结构和人工截图检查。

### 资源与错误

- 异步资产加载支持取消；组件卸载、重试和后端初始化失败不会残留 canvas、监听器或待决资源。
- 重复聚焦和细节层级切换后，geometry、material、texture、render target 和 light 数量达到稳定平台。
- WebGL2 释放上下文；WebGPU 释放 renderer 和项目注册的 GPU 资源。
- 资产失败使用明确回退，页面保持可选择、可聚焦，并给出可理解错误。
- console warning/error、页面异常和框架错误覆盖层必须为零，已确认的第三方构建提示单独记录。

### 性能与构建

- 性能探针先预热，再连续采样 5 秒并至少运行三次，记录中位数和范围。
- 同时记录页面 RAF、实际场景 render frame、Worker state 和资源存活数，避免用页面 RAF 代替场景渲染证据。
- 同一参考机的 Worker state 中位频率不得低于 M1 `33.36` 次/秒的 80%；更大规模承诺仍归 M5。
- Task 1 的两秒单次样本只作回归观察；Task 5 再按 5 秒、至少三次覆盖 WebGPU、WebGL2、桌面近景和手机，并根据正式矩阵确定 M2 最终硬阈值。
- 生产构建继续禁止 source map，验证正式 Worker、预览 Worker、唯一 WASM、渲染分块和新增资产清单。

## 测试矩阵

- 单元测试覆盖视觉配置选择、温度到恒星颜色、亮度参数、细节层级阈值、质量档位、资产回退和资源引用计数等纯函数。
- 集成测试覆盖异步资产取消、纹理缓存、材质构造、WebGPU/WebGL2 能力选择、资源注册和幂等释放。
- Playwright 覆盖代表天体近景、双后端、桌面、手机、失败回退、实际场景帧和资源稳定性。
- 完整 `pnpm check` 必须继续运行全部 M0 与 M1 回归流程。
- Playwright 使用仓库 `webServer` 自动管理生产预览，禁止测试自行留下常驻服务。
