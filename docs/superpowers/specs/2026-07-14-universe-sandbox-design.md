# STARY 宇宙沙盒设计规格

- 日期：2026-07-14
- 状态：已确认
- 产品范围：浏览器中的恒星系统级宇宙沙盒

## 1. 产品目标

STARY 是一个可创建、可破坏、可回放的宇宙沙盒。用户能够搭建恒星系统，修改天体参数，观察长期轨道，也能制造碰撞、引力弹弓和系统崩解。

产品同时守住四个目标：

1. 物理计算有明确依据，长期轨道误差可测量。
2. 天体、光照、大气和碰撞具有接近真实观测的画面。
3. 用户可以直接操作天体、速度和时间，不需要先学习复杂软件。
4. 桌面端提供完整体验，普通电脑和手机按能力自动降低画质与规模。

首版聚焦恒星系统。银河尺度、完整广义相对论和恒星全生命周期留给后续版本。

## 2. 已确认的产品原则

### 2.1 双模式体验

- 创造模式：放置天体、调整参数、预测轨道、辅助构建稳定系统。
- 实验模式：解除创建辅助，修改条件，观察碰撞、吞噬和系统崩解。
- 观察能力在两种模式中始终可用，包括自由相机、天体跟随和数据查看。
- 模式切换不重建场景，所有操作发生在同一个宇宙中。

### 2.2 双重显示

物理层始终使用真实质量、距离、速度和引力。显示层提供两种观测方式：

- 真实观测：保留实际半径、距离、亮度和空间感。
- 增强观测：允许放大天体轮廓、轨迹和微弱光线，但不修改物理数据。

所有视觉增强项都能单独关闭，并在界面中明确标识。

### 2.3 分层碰撞

碰撞结果由质量、材质、接触速度、入射角和撞击能量共同决定。系统区分擦碰、撞击坑、外层剥离、碎裂和合并。

- 主要碎块拥有真实质量，继续参与引力计算。
- 小碎屑只受主要天体影响，降低计算量。
- 尘埃由显卡批量模拟，负责碎片盘和尘埃云的视觉表现。

## 3. 核心用户流程

### 3.1 进入宇宙

网页打开后直接显示一个正在运行的恒星系统。默认场景包含恒星、两颗行星、卫星和小行星带。新建宇宙时可选择：

- 空白空间
- 类太阳系
- 双星系统
- 随机系统

### 3.2 创建天体

1. 用户选择恒星、岩石行星、气态行星、卫星、黑洞或小行星群。
2. 点击空间确定初始位置。
3. 拖动指针拉出初速度向量。
4. 系统快速试算未来轨迹，并显示稳定、碰撞或逃逸风险。
5. 用户确认后，天体进入正式模拟。

### 3.3 操作与实验

- 拖动天体改变位置。
- 拖动速度向量改变运动状态。
- 修改质量、半径、材质、温度和自转。
- 暂停、单步、倒退或加速时间。
- 跟随、环绕或近距离观察选中天体。
- 回到历史节点，从该节点建立新的实验分支。

## 4. 界面设计

主画面始终由宇宙场景占满，不使用承载主体验的卡片容器。

- 顶部中央：观察、创造、实验模式分段开关。
- 左侧：可折叠的天体目录，显示恒星、行星和卫星的层级关系。
- 底部：暂停、单步、倒退、倍速和时间刻度。
- 右侧：选中天体后出现属性面板。
- 画面内：轨道、速度向量、引力范围、碰撞预警和选中标记。

功能色保持克制：

- 稳定轨道：青绿色
- 风险提示：琥珀色
- 碰撞预警：红色
- 普通数据：白色或中性灰

面板采用观测仪器风格。图标按钮使用通用符号并提供悬停说明。手机端将天体目录和属性面板收进底部抽屉，保留场景与时间控制。

## 5. 技术架构

系统采用混合架构，物理、画面和界面互相隔离。

### 5.1 模块职责

| 模块 | 职责 |
| --- | --- |
| 应用外壳 | 页面生命周期、模式切换、能力检测和全局错误处理 |
| 创造工具 | 放置、拖动、速度向量、参数编辑和轨道预览 |
| 物理线程 | 引力积分、时间推进、近距离相遇和物理事件 |
| 碰撞引擎 | 材质模型、碰撞分类、质量分配和主要碎块生成 |
| 画面引擎 | 天体、光照、大气、粒子、轨道和相机 |
| 历史系统 | 操作日志、快照、撤销、回放和实验分支 |
| 场景存储 | 自动保存、导入、导出、校验和版本迁移 |
| 界面层 | 天体目录、属性面板、时间轴和画质设置 |

### 5.2 主要技术选择

- Three.js 负责场景组织与渲染。
- WebGPU 是首选渲染后端，WebGL2 作为兼容回退。
- REBOUND 作为成熟的多体引力底座，编译为 WebAssembly 后在浏览器运行。
- 物理模块运行在 Web Worker 中，避免复杂计算阻塞界面。
- 碰撞扩展使用 Rust 编译为 WebAssembly，与 REBOUND 的轨道结果连接。
- TypeScript 开启严格模式，负责界面、工具、消息协议和状态组织。

### 5.3 数据流

1. 创造工具把用户输入转换为带单位的物理参数。
2. 物理线程执行短期试算，返回轨迹点和风险事件。
3. 用户确认后，历史系统先记录操作，物理线程再加入天体。
4. 物理线程按固定频率输出位置、速度和事件。
5. 画面引擎在相邻两次结果之间插值，保证移动平滑。
6. 碰撞事件进入碰撞引擎，结果返回物理线程并写入历史记录。
7. 场景存储按间隔和关键事件生成快照。

画面帧率和物理频率相互独立。画面变慢时，轨道结果仍按物理步长推进。

## 6. 物理设计

### 6.1 数据和单位

内部统一使用千克、米、秒和双精度浮点数。每个主要天体至少包含：

- 唯一标识与名称
- 质量与半径
- 三维位置与速度
- 自转与朝向
- 岩石、冰、气体或黑洞等材质分类
- 温度、反照率和发光参数
- 程序化外观种子

显示单位根据数量级自动切换为千米、天文单位、小时、天或年。

### 6.2 引力与积分

- 主要天体上限为 512 个，彼此进行完整的互相引力计算。
- 轨迹粒子上限为 10,000 个。它们没有主动引力，但会受到全部主要天体影响。
- 视觉碎屑的高画质目标为 50,000 个。它们由显卡批量计算，只采用碰撞残体和附近主导天体的引力。
- 稳定系统使用适合长期轨道的辛积分方式。
- 近距离相遇和高度偏心轨道切换到高精度自适应积分。
- 系统持续监控总能量、总动量和角动量。
- 误差越过安全阈值时，系统降低时间倍率或暂停并给出原因。

### 6.3 碰撞结果

碰撞先计算单位质量撞击能量，再与材质破坏阈值比较。结果包含：

- 擦碰后分离
- 局部撞击坑和物质喷射
- 大气或外层剥离
- 部分碎裂并保留最大残体
- 灾难性碎裂
- 低速合并

每次碰撞最多生成 64 个主要碎块，剩余质量进入轨迹粒子或视觉尘埃。主要碎块、轨迹粒子和尘埃记录的质量总和必须等于碰撞前总质量。非弹性碰撞损失的机械能进入热量、形变和破碎能量账本，不能直接消失。

### 6.4 黑洞和相对论边界

- 黑洞拥有真实质量、引力和吞噬范围。
- 首版对黑洞和高质量恒星附近的轨道使用一阶后牛顿修正，用于表现近日点进动。
- 首版不求解完整时空弯曲，也不模拟黑洞内部。
- 一阶修正不适用于接近事件视界的轨道；进入该范围的天体按吞噬事件处理。
- 吸积盘只在周围存在可吸积物质时出现。

### 6.5 时间与回放

时间倒退使用快照和事件重放。发生不可逆碰撞后，系统从较早快照重新运行到目标时刻，避免直接反算碎片重组。

存档保存初始条件、随机种子、操作记录和必要快照。同一版本、相同输入的重放结果必须在规定数值容差内一致。

## 7. 画面设计

### 7.1 天体表面

- 真实太阳系场景优先使用 NASA 公共数据。
- 用户创建的岩石行星根据材质、温度、含水量和种子生成地形。
- 气态行星生成纬向云带、风暴和差异旋转。
- 恒星颜色根据表面温度计算，亮度根据质量和半径推算。
- 城市灯光等人为特征只在场景条件明确支持时出现。

### 7.2 大气、云和光照

- 大气使用光线散射模型，正确表现地平线厚度和颜色变化。
- 云层拥有高度、移动和阴影。
- 日食、月食、行星环阴影和多恒星照明实时计算。
- 高动态范围曝光模拟观测明暗适应。
- 行星环近看呈现颗粒结构，远看形成连续环带。

### 7.3 大尺度精度

- 画面围绕相机重新定位坐标，避免远离原点后出现抖动。
- 恒星系统远景、轨道区和近景表面分层渲染。
- 相机速度根据观察尺度平滑变化。
- 真实观测和增强观测共用同一份物理状态。

### 7.4 高能现象

- 碰撞特效从真实接触点和喷射方向生成。
- 熔融物与碎屑根据温度逐渐冷却变暗。
- 黑洞画面包含背景光线弯曲，并由周围物质决定吸积盘状态。
- 特效强度由物理事件提供的能量和物质量驱动。

## 8. 存储与分享

首版采用本地优先策略，不要求账号或服务器。

- 使用浏览器本地存储自动保存。
- 支持将完整宇宙导出为单个文件。
- 支持导入他人分享的宇宙文件。
- 存档包含格式版本，并提供向后迁移。
- 导入前校验结构、文件大小、数字范围和对象数量。
- 迁移失败时保留原文件并给出可理解的错误原因。

## 9. 性能与降级

系统启动时检测设备能力，并允许用户手动调整。

桌面性能验收使用以下参考级别：六核桌面处理器、16 GB 内存，以及性能不低于 NVIDIA GTX 1660 或 Apple M1 的图形设备。低于参考级别的设备进入自适应降级，不承担完整规模的 60 FPS 门槛。

降级顺序：

1. 降低体积云和大气采样质量。
2. 降低阴影分辨率和远处天体细节。
3. 减少尘埃与无质量碎片数量。
4. 降低画面刷新率。
5. 限制新建主要天体数量，并说明原因。

主要天体的质量、位置、速度和碰撞结果不能因画质降级而改变。手机端保留观察、轻量编辑和小规模实验，复杂碰撞自动减少视觉碎屑。

## 10. 异常处理

- 极端参数在执行前显示风险与预计计算规模，用户可以继续。
- 能量误差过大时自动降速；无法恢复时暂停并保留快照。
- 物理线程停止响应时，从最近完整快照重启。
- 碎片超过设备上限时合并远处小碎片，保留主要碎块。
- WebGPU 初始化失败时自动回退到 WebGL2。
- 存档损坏时尝试恢复最近完整快照，并保留损坏文件供用户导出。
- 所有跨线程消息都经过结构校验，拒绝缺失字段和非有限数字。

## 11. 首版范围

首版包含：

- 四种初始场景模板
- 六类可创建天体
- 观察、创造、实验三种模式
- 多体引力与轨道预测
- 时间控制、历史回放和实验分支
- 分层碰撞与碎片表现
- 真实观测与增强观测
- 本地存档、导入和导出
- 自适应画质与兼容回退

首版暂缓：

- 银河尺度模拟
- 完整广义相对论
- 恒星完整生命周期
- 行星表面降落与人物移动
- 在线多人协作、账号和云存档

## 12. 测试与验收

### 12.1 核心自动测试

- 双天体圆轨道和椭圆轨道
- 三体拉格朗日点
- 引力弹弓
- 双星与行星系统
- 正面撞击、斜向擦碰和灾难性碎裂
- 碰撞质量、线动量和角动量守恒
- 快照恢复与确定性重放
- 存档结构校验和版本迁移
- 极端数值、无效数字和对象数量上限

### 12.2 物理验收

- 默认精度下运行 1000 个轨道周期，总能量相对误差不高于 `10^-5`。
- 碰撞前后相对质量误差不高于 `10^-12`。
- 碰撞前后相对线动量误差不高于 `10^-10`。
- 包含天体自转后的相对角动量误差不高于 `10^-8`。
- 碰撞机械能变化必须进入热量、形变或破碎能量账本，相对记账误差不高于 `10^-6`。
- 时间倍率过高时主动降低速度，不能静默牺牲物理精度。

### 12.3 性能验收

- 512 个主要天体在参考桌面设备上保持每秒至少 30 次物理更新。
- 50,000 个视觉碎屑时，参考桌面设备保持 60 FPS。
- 画面负载上升时，物理线程保持独立推进。
- WebGPU 与 WebGL2 回退路径都能完成创建、碰撞、保存和回放流程。

### 12.4 交互与视觉验收

- 使用浏览器自动化验证创建、编辑、时间控制、导入导出和恢复流程。
- 使用桌面与手机截图检查布局、文字溢出、控件遮挡和主要画面质量。
- 通过画布像素检查确认三维场景实际渲染，避免空白画布被误判为成功。
- 纯配色、布局和外观不编写单元测试。

## 13. 完成定义

首版完成需要同时满足：

1. 用户能从模板或空白场景创建一个恒星系统。
2. 天体按多体引力运行，并能显示可解释的误差指标。
3. 用户能制造一次分层碰撞，并观察主要碎块继续运行。
4. 用户能保存、关闭、恢复和重放实验。
5. 真实观测与增强观测都可用，切换不改变物理状态。
6. 核心自动测试、静态检查、构建和浏览器验收全部通过。
