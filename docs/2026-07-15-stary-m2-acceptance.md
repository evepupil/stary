# STARY M2 验收记录

## 结论

M2 真实画面通过验收，可以进入 M3 碰撞与碎片阶段。

功能基线建立在 M2 Task 4 提交 `f40bf9b` 之上。Task 5 增加正式性能矩阵、场景资源与渲染生命周期诊断、失败分块页面内重试、资源循环、布局截图和构建门禁，没有改变正式物理协议、SI 天体状态或 REBOUND 积分配置。

## 画面与物理边界

- 太阳、八大行星和月球继续读取固定 JPL J2000 SI 状态。表面、灯光、大气、云层、环、黑洞光子环和曝光只读取物理状态，不会回写质量、半径、位置、速度或时间。
- 固定太阳系表面与地球云图来自仓库内锁定的 CC BY 4.0 资产，运行时不依赖外部站点。动态创建天体使用稳定种子的程序化外观。
- 天体球面使用真实半径。全景定位使用独立屏幕空间标记；近景移动渲染原点只改变 Float32 画面坐标，不改变 SI 世界状态。
- 最多四颗质量最大的恒星提供平方距离衰减灯光。遮挡比例进入地表明暗、大气、云影、环影和曝光。
- 黑洞使用真实 Schwarzschild 半径、`2.598 Rs` 可观察阴影与光子环。当前动力学仍是牛顿多体引力，画面没有吸积盘、喷流、全屏背景扭曲或广义相对论光线追踪。
- WebGPU 提供黑洞冷色透镜光晕，WebGL2 保留暗核和光子环。两条后端保持可观察组成一致，不承诺逐像素相同。

## 浏览器矩阵

- 桌面 `1440×900` 默认后端实际进入 WebGPU，覆盖太阳系全景和地球表面近景。
- 桌面 `1440×900` 强制 WebGL2，使用相同地球近景与性能窗口，避免把后端差异和手机尺寸混在一起。
- 桌面 `1280×720` 默认 WebGPU 地球近景检查左右面板、顶栏、模式切换和时间条。
- 手机 `390×844` 强制 WebGL2，覆盖地球近景、黑洞创建与聚焦、天体目录、数据抽屉和时间条。
- 原有回归继续覆盖太阳、地球、土星、大气、云层、食相、曝光、环影、黑洞像素、全景、聚焦、时间控制、创建、编辑与删除。

所有新增正常流程都收集 console warning/error、pageerror 和 requestfailed。场景分块失败用例只白名单主动中止的唯一请求及其对应 Chrome `Failed to load resource`，恢复后的其他错误仍为零容忍。

## 资源与恢复

`data-visual-resource-counts` 现在包含以下稳定平台：

- 场景图按对象身份去重的 geometry、material、texture、light 和 object。
- 表面、云层与行星环纹理缓存的 loading、ready、reference 和 waiter。
- 黑洞共享程序化纹理池的 entry 与 reference。
- Scene 与 Renderer 的 created、disposed 和 active。
- 当前管线没有项目级 render target，`renderTargets` 固定为 `0`。

资源测试先访问地球和土星完成纹理与材质预热，然后连续三轮执行地球近景、土星近景、太阳系全景、创建草稿并取消、编辑并取消，以及 `1280×720` 与其他桌面尺寸之间的 resize。每轮等待真实场景帧后，完整资源快照都与预热基线相等，页面始终只有一个 canvas。

首次中止 `observatory-scene` 动态分块后，应用进入安全暂停。点击重试会给同源哈希分块增加新的查询参数，绕过浏览器缓存的失败 ESM 结果。恢复后诊断为：

| 指标              | 结果 |
| ----------------- | ---: |
| Renderer created  |    2 |
| Renderer disposed |    1 |
| Active Renderer   |    1 |
| Scene created     |    1 |
| Scene disposed    |    0 |
| Active Scene      |    1 |
| 已连接 canvas     |    1 |

失败尝试创建的 canvas 已脱离文档，WebGL2 会同时调用 renderer dispose 与 context loss，WebGPU 调用 renderer dispose；重复释放保持幂等。

## 五秒性能矩阵

命令：`pnpm test:performance`

每个场景先等待 60 个真实场景帧和资源稳定，再连续采样三次、每次至少五秒。表中为中位数，方括号为三次样本范围。

| 场景                |            RAF 次/秒 |         Render 次/秒 |   Worker state 次/秒 |
| ------------------- | -------------------: | -------------------: | -------------------: |
| 桌面全景 WebGPU     | 60.13 [60.04, 60.17] | 60.13 [60.04, 60.77] | 32.98 [32.71, 33.16] |
| 桌面地球近景 WebGPU | 60.09 [60.05, 60.19] | 60.05 [59.99, 60.29] | 32.92 [32.74, 33.00] |
| 桌面地球近景 WebGL2 | 60.11 [60.00, 60.13] | 59.60 [59.51, 59.93] | 32.95 [32.89, 32.96] |
| 手机地球近景 WebGL2 | 60.18 [60.01, 60.19] | 59.99 [59.98, 60.41] | 32.99 [32.89, 33.19] |

页面 RAF 和实际场景 Render 中位频率硬门槛均为 `48 次/秒`。Worker state 中位频率硬门槛为 M1 `33.36 次/秒` 的 80%，即 `26.69 次/秒`。四个场景全部通过，12 个样本的采样前后资源快照完全相等。

这些数字只代表当前参考机、Chrome、默认 10 体和指定近景。它们不能外推到 512 个主要天体、50,000 个视觉碎屑、低性能设备或其他浏览器。

## M2 已知限制

- 当前真实浏览器验收以 Chrome 149 为主。Safari、Firefox、更多显卡和低性能设备进入 M5。
- 资源诊断覆盖 Three.js 场景直接持有的内置材质纹理和项目管理的缓存、共享池与生命周期，不提供浏览器驱动内部显存字节。未来引入 ShaderMaterial、TSL uniform 纹理或项目级 render target 时必须扩展统计。
- 手机数据抽屉会覆盖画布的一部分，适合查看数据和操作；关闭抽屉后再观察完整天体近景。
- 表面资产是固定时间片或合成观测外观，金星使用雷达增强表面。大气、云影、环影、食相明暗和黑洞光晕是双后端可审计近似。
- 黑洞没有吸积盘、喷流、全屏透镜扭曲和相对论动力学。碰撞、碎裂、熔融与吞噬结果进入 M3。
- 当前性能只覆盖默认 10 体。512 个主要天体、50,000 个视觉碎屑、设备分档和长期压力测试进入 M5。

## 进入 M3 的门槛

- 真实太阳系表面、环、大气、云层、光照、遮挡、曝光和黑洞都有桌面与手机画布证据。
- 全景、轨道区和真实半径近景使用稳定的移动渲染原点、连续相机与明确 LOD。
- WebGPU 与 WebGL2 的关键观察和创建流程可用，失败场景可以释放旧资源并恢复单一画布。
- 正式性能、生产包、资源平台、布局截图和已知边界都有可重复记录。
- 视觉增强与正式 SI 物理状态保持分层，M3 可以在同一 Worker 与画面底座上接入碰撞事件。
