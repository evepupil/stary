# STARY M4 历史与存档实施规划

对应 [roadmap M4](roadmap.md),模块归档见 [历史与存档](模块设计/历史与存档.md)。产品要求来自设计规格 3.3、5.1、6.5、8、10 与 12 节。

## 目标

用户可以把宇宙的任意关键时刻留成快照,跳回任意历史节点并从那里开出新的实验分支;宇宙自动保存在浏览器本地,也能导出成单个文件分享给别人导入。同一版本、相同输入的重放在数值容差内一致。

## 核心决策

| 决策                                                                 | 理由                                                                                       |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 快照 = 完整 `PhysicsState` + 模拟时间 + 修订号 + 时间倍率,自包含可恢复 | 协议 v3 的状态已携带主要天体、被动资产与累计账本;不需要额外物理信息即可重建宇宙           |
| 元数据(标签、创建时间)不进内容哈希                                    | 改名不改身份;完整性校验只覆盖可恢复内容                                                   |
| 时间倒退与回放 = 恢复快照后由固定 WASM 重新推进,不反算碎片            | 设计规格 6.5;固定 REBOUND/Collision WASM 在同构建下确定性重跑(M3 Task 7 已在 Node 证实) |
| 恢复历史节点并继续 = 自动创建实验分支,原时间线不被覆盖                | 设计规格 3.3;历史是一棵树,节点为快照,边为推进                                           |
| 自动关键帧挂在天体替换与碰撞批次上,另加手动快照                       | 这两类事件已经是修订号递增的原子边界,天然适合做关键帧                                     |
| 本地存储用 IndexedDB,存储层与领域模型隔离                             | 512 天体 + 10,000 被动资产的状态可达 MB 级,localStorage 容量不够;测试用内存适配器         |
| 文件格式带 `format`/`formatVersion`,导入走严格 Zod 校验与大小上限     | 设计规格 8;结构、数值范围与对象数量由协议 schema 复用,迁移失败保留原文件与可读错误       |
| 逐命令操作日志重放暂缓,首版回放以快照链为准                           | 快照跳转 + 重新积分已覆盖倒退、回放与分支;命令级重放引擎复杂度高,收益留待后续版本         |

## 职责边界

- `src/history/` 负责快照模型、序列化、完整性、时间线树与存储适配接口,全部纯 TypeScript,可在 Node 测试。
- `src/physics/protocol/` 升级到 v4:新增完整状态恢复命令,保持既有命令语义不变。
- `src/physics/runtime/` 负责恢复命令的候选实例、首帧验收、原子切换与失败回滚,复用碰撞事务的候选模式。
- `src/platform/storage/` 负责 IndexedDB 适配器与能力探测。
- `src/features/archive/` 负责时间轴面板、分支操作、导入导出界面;显示层不写单测。

## 任务拆分

### Task 1:快照模型与序列化底座

- 快照 schema(格式 v1):`format`、`formatVersion`、内容(模拟时间、修订号、倍率、完整 `PhysicsState`)、可变元数据(标签、创建毫秒时间戳)与 FNV-1a 64 内容哈希。
- 规范化 JSON 序列化:键排序、f64 精确往返、`-0` 归一为 `0`;快照 ID 由内容哈希派生,改标签不改身份。
- 编解码器:创建、编码、解码、完整性校验;解码入口带大小上限与结构化错误码(非法 JSON、格式不符、版本不支持、结构非法、哈希不匹配)。
- 黄金哈希样例锁定规范化规则,防止后续无意破坏已分享文件的哈希。

完成门槛:极端数值(`1e308`、次正规数)逐位往返;篡改必被哈希拒绝;未知字段、错误版本、超大输入全部拒绝。

### Task 2:协议 v4 与完整状态恢复

- 协议升级到 v4:新增 `restoreSnapshot` 命令,携带完整 `PhysicsState`、目标模拟时间与期望修订号;响应复用原子替换语义(候选实例、首帧验收、成功后修订号递增、失败回滚保留原实例)。
- worker 初始化支持从快照冷启动(恢复"物理线程停止响应时从最近完整快照重启")。
- controller 与观测台状态链接入恢复命令,守恒基线在恢复后重建;恢复清空碰撞批次记录。
- 拒绝路径:修订冲突、快照时间冲突、容量超限、非法状态,全部有定向测试。

### Task 3:历史时间线与实验分支

- 时间线树模型:节点 = 快照引用 + 触发原因(初始、天体替换、碰撞批次、手动、恢复),边 = 推进;纯函数实现增删查与分支派生。
- 自动关键帧:`bodiesReplaced` 与 `collisionBatchResolved` 落地时追加节点;手动快照追加当前状态节点。
- 从任意节点恢复并继续 → 以该节点为父创建新分支;活动分支指针与分支命名。
- 树的容量上限与最旧自动关键帧修剪策略(手动快照不自动淘汰)。

### Task 4:本地自动存档

- `src/platform/storage/` IndexedDB 适配器:打开/读写/列举/删除,版本化对象仓库;内存适配器供测试与不可用环境回退。
- 自动保存:关键帧节流写入,页面隐藏/关闭时冲刷;存储失败降级为仅内存并明确提示。
- 启动恢复:发现既有存档则提供继续或新建;存档损坏时回退最近完整快照,损坏数据保留导出。

### Task 5:历史界面与回放

- 时间轴面板:按分支列出节点(时间、原因、标签),支持跳转、重命名、删除、手动快照;桌面浮层与手机抽屉,与创建/编辑互斥。
- 回放:跳转到节点后可直接播放向前推进;跳回旧节点继续时明确显示新分支。
- 恢复期间的相机与选择处理:选中天体消失时回退,焦点天体保持或回全景。

### Task 6:文件导出与导入

- 导出:当前快照或整棵历史树为单个 JSON 文件(格式 v1,含内容哈希)。
- 导入:大小上限、严格 schema、哈希校验、对象数量与数值范围(复用协议 caps);导入快照进入新分支,导入历史树整树并入。
- 版本迁移入口:v1 直通,未知版本给出可读错误并保留原文件。

### Task 7:M4 综合验收

- 快照恢复与确定性重放、分支派生、自动存档、损坏恢复、导出导入全链覆盖。
- 记录生产包变化、恢复延迟与已知边界;更新路线图、验收记录与模块归档。
- 完成门槛:完整代码门禁通过;浏览器证据按远程环境约定处理。

## 测试矩阵

- 纯函数:规范化序列化往返、哈希稳定黄金样例、篡改拒绝、时间线树操作、修剪策略、迁移入口。
- Worker 与协议:v4 严格解析、旧版本拒绝、恢复命令的候选/回滚/冲突、恢复后守恒基线、恢复后继续积分与再碰撞。
- 存储:内存与 IndexedDB(fake-indexeddb 或浏览器)读写、损坏数据回退、节流与冲刷。
- 浏览器(留待真实 GPU 环境):保存-刷新-恢复、跳转-分支-继续、导出-导入、手机时间轴抽屉。

## 明确暂缓

- 逐命令操作日志与命令级重放引擎。
- 跨浏览器逐位一致回放(只承诺数值容差内一致)。
- 在线分享、账号与云存档。
- 历史节点的差异压缩与增量存储(首版全量快照)。
