# 物理核心

## 当前状态

M0 Task 3 已建立正式跨线程协议、运行时结构校验和会话顺序门。REBOUND/WASM 隔离原型继续作为固定物理产物来源。真实物理 Worker、REBOUND 适配和时间推进留到 Task 4。

## 设计

物理核心负责真实单位的天体状态、引力积分、时间推进和守恒诊断。它运行在独立 Web Worker 中，界面和画面只能通过带版本、模拟时间与序号的消息协议访问状态。

当前确认的底座是 REBOUND 5.0.1 WebAssembly。REBOUND 负责多体引力积分；后续 Rust 模块负责分层碰撞。物理坐标统一使用千克、米、秒和双精度数值。渲染缩放与视觉增强留在画面适配层。

正式模块需要提供：

- 明确的模拟实例生命周期和安全暂停
- 天体增删改与运行时数据校验
- IAS15、WHFast 等积分器的场景化选择
- 固定物理步进与独立的状态输出频率
- 总能量、线动量和角动量监测
- Worker 错误、过载和重启处理
- 确定性回放所需的输入和版本记录

### 正式消息协议

正式协议版本固定为 `1`。主线程发给 Worker 的命令和 Worker 返回主线程的响应都是按 `type` 区分的判别联合。大白话说，代码先看 `type`，随后就能知道这条消息必须带哪些字段。

每条消息都有以下公共字段：

| 字段                    | 含义                                               |
| ----------------------- | -------------------------------------------------- |
| `version`               | 固定为 `1`，其他版本直接拒绝                       |
| `sessionId`             | 一次 Worker 生命周期的唯一会话标识，历史上不可复用 |
| `sequence`              | 当前方向消息流中的非负安全整数，接收端要求严格递增 |
| `simulationTimeSeconds` | 当前模拟时间，单位秒，必须大于等于 `0`             |

主线程命令：

| `type`         | 额外数据                                             |
| -------------- | ---------------------------------------------------- |
| `initialize`   | 初始 `bodies`；固定 `sequence=0`、模拟时间 `0`       |
| `start`        | 无                                                   |
| `pause`        | 无                                                   |
| `step`         | 正数 `stepSeconds`                                   |
| `setTimeScale` | 正数 `timeScale`，只改变现实时间与模拟时间的推进比例 |
| `dispose`      | 无                                                   |

Worker 响应：

| `type`     | 额外数据                             |
| ---------- | ------------------------------------ |
| `ready`    | 固定 `sequence=0`、模拟时间 `0`      |
| `state`    | `bodies` 和能量、线动量、角动量诊断  |
| `status`   | `runState` 和 `timeScale`            |
| `error`    | 稳定错误码、可读消息和 `recoverable` |
| `disposed` | 无                                   |

### 物理数据

天体只包含跨实现共享的数据：`id`、`massKg`、`radiusMeters`、`positionMeters` 和 `velocityMetersPerSecond`。位置和速度都是三维向量。状态诊断使用 `totalEnergyJoules`、`totalLinearMomentumKgMetersPerSecond` 和 `totalAngularMomentumKgMetersSquaredPerSecond`。

字段名直接写出 SI 单位，避免调用方靠上下文猜单位。协议中没有 Three.js 对象、画面缩放、REBOUND 指针或 Emscripten 内存视图。

所有数值必须有限。质量必须大于 `0`，半径和模拟时间必须大于等于 `0`，步长与时间倍率必须大于 `0`。同一消息中的天体 `id` 不能重复。主要天体数量限制为 `1..512`，上限由 `MAX_MAJOR_BODY_COUNT` 导出，供协议使用方复用。协议对象使用严格模式，额外字段也会被拒绝。

## 实现细节

### 协议目录

正式协议位于 `src/physics/protocol/`：

- `schemas.ts` 使用精确锁定的 Zod `4.4.3` 定义双向消息、天体、向量和诊断结构，并从 schema 推导 TypeScript 类型。
- `parse-message.ts` 接收 `unknown`，分别提供 `parseMainToWorkerMessage` 和 `parseWorkerToMainMessage`。解析失败会抛出 Zod 校验错误，非法数据不能进入物理逻辑。
- `session-sequence-gate.ts` 提供独立的 `SessionSequenceGate`，只负责当前会话和消息顺序。
- 两组测试覆盖合法消息、字段缺失、未知版本、额外字段、非有限数、质量/半径/时间边界、重复天体、握手固定值、512 天体上限和双向消息类型。

### 启动握手

启动时序固定如下：

1. 主线程创建 Worker 和一个从未使用过的 `sessionId`。
2. 主线程立即发送 `initialize`，该消息固定为 `sequence=0`、`simulationTimeSeconds=0`，并携带初始天体。
3. Worker 先解析 initialize，再从中取得 sessionId 并建立主线程到 Worker 的顺序门。
4. 物理模块初始化成功后，Worker 发送同 session 的 `ready`，固定为 `sequence=0`、`simulationTimeSeconds=0`。
5. 主线程先解析 ready，再交给预先按该 session 配置的 Worker 到主线程顺序门。
6. 两个方向的后续消息使用严格递增序号。

主线程不会等待一个不带 session 的预 ready。Worker 也不会自行选择 sessionId。这样启动消息和所有后续消息都处于同一版协议与同一会话边界内。

### 解析与顺序

接收端先调用对应解析函数，成功后再把 `sessionId` 和 `sequence` 交给顺序门。顺序门只接受当前 session 中严格大于上次已接收序号的消息；重复、倒退和旧 session 消息都返回明确拒绝原因，且不会推进门状态。序号允许跳跃，便于后续丢弃无需渲染的中间状态。

Worker 重启时，主线程必须生成一个从未使用过的 `sessionId`，再显式调用 `resetForWorkerRestart`。顺序门会记录所有退役 sessionId，并清空新会话的上一序号。旧 Worker 即使稍后送达更大序号，也会因 session 不匹配被拒绝；A 到 B 再回到 A 的复用同样会被拒绝。

主线程到 Worker、Worker 到主线程是两条独立消息流，各自持有一个顺序门，避免双向序号互相干扰。

### REBOUND/WASM 原型

`spikes/rebound-wasm/` 是当前唯一实现，职责限于验证交付路径：

- `source-lock.json` 固定 REBOUND 源码和 Emscripten 镜像。
- `scripts/` 下载并校验源码，在固定容器中生成 `.mjs` 和 `.wasm`。
- `src/rebound_bridge.c` 暴露最小 C 接口。
- `web/rebound-client.mjs` 提供原型 JavaScript 适配。
- `web/physics-worker.mjs` 和静态页面验证浏览器 Worker 加载。
- `scripts/static-server.mjs` 为验收页提供正确的模块与 WASM MIME，并限制可访问目录。
- `artifact-lock.json` 和 `scripts/verify.ps1` 保证固定输入重建后的补丁与 WASM 产物哈希一致。
- `web/sun-earth-scenario.mjs` 固定太阳-地球质心场景、解析周期和验收容差。

REBOUND 的原始 Emscripten 路径会在较长的单次积分中调用 `emscripten_sleep(0)`，用于上游网页显示刷新。当前构建没有使用 `ASYNCIFY`，并应用固定补丁禁用这一个 120Hz 显示让出调用。物理运行在专用 Worker；正式线程必须把异步分片推进作为 JavaScript 调度职责，并在片段之间让出事件循环。

原型接口仍不直接连接正式界面。Task 4 必须通过正式协议包装 REBOUND 适配器，禁止把原型对象或 Emscripten 接口发布到消息边界。
