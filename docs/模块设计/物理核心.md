## 当前状态

M3 Task 4 已完成。固定 Rust Collision WASM 能独立处理经典二体碰撞、黑洞吞噬、确定性残体重建、材料路由、容量和守恒账本；TypeScript 参考实现、严格 schema、低层 WASM 适配器和真实跨语言对照已经落地。正式 REBOUND Worker 继续运行 JPL J2000 太阳系 10 体，公共协议、轨道预览、controller 和观测台状态链统一使用 v3。固定 C 桥能够推进到目标或首个连续接触，但正式运行循环仍调用 `integrateTo`；Task 5 才会把接触批次、Collision WASM 结果和候选 REBOUND 原子切换串起来。

## 设计

物理核心负责真实单位的天体状态、引力积分、时间推进和守恒诊断。它运行在独立 Web Worker 中，界面和画面只能通过带版本、模拟时间与序号的消息协议访问状态。

当前确认的底座由 REBOUND 5.0.1 WebAssembly 和固定 Rust Collision WebAssembly 组成。REBOUND 负责多体引力积分与连续接触；Collision WASM 负责分层碰撞候选。物理坐标统一使用千克、米、秒和双精度数值。渲染缩放与视觉增强留在画面适配层。

### M3 碰撞边界

M3 使用事件式推进替代单步和连续运行中的直接 `integrateTo`。REBOUND C 桥用 simulation checkpoint、曲率上界和递归回放负责最早接触与同刻 pair 集合；Rust/WASM 负责二体 EDACM 分类、材料剥离、残体和守恒账本；TypeScript Worker 负责接触图、严格校验与候选实例原子切换。

Task 3 的 C 桥在一次原生 `reb_simulation_integrate()` 中挂接 heartbeat，保持无事件路径的 IAS15 步序、末步和 `dt_last_done` 语义。每个接受步保留完整 checkpoint；区间先用步首距离的一半构造加速度 enclosure，验证相对运动无法越过该下界后，才允许用 `A_rel h^2/8` 和径向变化上界排除端点弦外的弯曲接触。无法证明的区间从同一个不可变步首直达采样时刻并左优先细分，禁止从人工中点继续积分，也禁止用端点方向猜测整段路径。

穿透使用真实半径和的最早零点，正切使用径向速度零点，距离容差固定为半径比例、世界坐标 ULP 与 `256 * DBL_EPSILON * worldScale` 回放评估预算的最大值。后者是当前固定 IAS15 回放的浮点位置预算；遇到 enclosure、深度、节点或 replay 预算无法闭合时返回数值错误并恢复到该接受步步首，禁止按无事件接受。零半径 pair 没有接触面，但它们的引力仍进入逐区间 separation enclosure。

接触结果保留到显式 `clearPendingContact()`。确认后的正切 pair 只有在弦曲率下界证明未重新穿透时才会被抑制，完全分开或重新接近后自动武装；初始重叠且正在接近或静止会在当前时刻产生事件，明确分离的重叠体通过 enclosure 与径向变化证明后继续推进。适配器解析失败使用独立 discard 释放读取缓冲，不会确认或抑制未解决事件。C 句柄使用单调 token 查表，重复销毁或旧 token 无法释放后来创建的实例。

协议已经升级到 v3，增加命令回执序号、材料层、自转角动量、转动惯量因子、tracer、dust cohort、碰撞批次和累计耗散账本。成功批次只递增一次 `bodyRevision`；失败保留接触时刻的旧实例并安全暂停。共享天体的三体或更多同刻接触首版返回模型范围错误，禁止按二体顺序计算。

Task 4 使用 Rust/Cargo `1.96.0` 和 `wasm32-unknown-unknown`，固定构建运行在锁定摘要的 `rust:1.96.0-bookworm`、`linux/amd64` 容器。内核通过 ABI 版本 `1` 的八个 C 导出工作：TypeScript 创建单调 token、分配 UTF-8 JSON 请求缓冲、原地解析成响应，再重新取得可能因 `memory.grow()` 变化的指针并在 `finally` 中销毁。请求上限为 `1 MiB`，响应上限为 `16 MiB`；重复 resolve、重复销毁和 stale token 都有明确状态且不会影响新上下文。

内核批次只接受互不共享参与体的二体事件，并按 UTF-8 `eventId` 稳定排序。经典分支固定 EDACM/Genda、材料剥离、主要残体与一个聚合被动资产的工程重建；黑洞分支使用独立牛顿吞噬账本。任一事件失败时返回整批错误 envelope，不产生部分结果。真实 Collision WASM 已与 TypeScript 参考实现对照 merge、hit-and-run、灾难性破坏、批次排序和黑洞吞噬；离散字段精确一致，已记录的跨语言浮点末位差异使用有界相对容差。

生产 Worker 已引用 Collision WASM URL，使构建产物能够锁定并验证该二进制。`PhysicsWorkerRuntime` 当前只保存这个 URL，没有实例化内核，也没有消费碰撞结果。Task 5 会统一切换单步和连续运行到 `advanceUntilEvent`，拒绝共享参与体的多体分量，解析并复算 Rust 候选与守恒账本，创建候选 REBOUND，全部门禁通过后一次递增修订号并原子替换。

碰撞诊断拆成事件总账、REBOUND 活跃体积分漂移、被动碎片账和省略反作用账。visual debris 没有物理质量，画质设置不能改变任何一套物理结果。

完整来源、公式、任务和暂缓范围记录在 `docs/2026-07-15-stary-m3-collisions-debris.md` 与 `docs/模块设计/碰撞与碎片.md`。

正式模块当前提供：

### 正式消息协议

正式协议当前版本为 `3`。主线程发给 Worker 的命令和 Worker 返回主线程的响应都是按 `type` 区分的判别联合。代码先看 `type`，随后就能知道这条消息必须带哪些字段。v1 和 v2 消息都会被严格拒绝，主线程与 Worker 必须同批发布。

每条消息都有以下公共字段：

| 字段                    | 含义                                               |
| ----------------------- | -------------------------------------------------- |
| `version`               | 固定为 `3`，其他版本直接拒绝                       |
| `sessionId`             | 一次 Worker 生命周期的唯一会话标识，历史上不可复用 |
| `sequence`              | 当前方向消息流中的非负安全整数，接收端要求严格递增 |
| `simulationTimeSeconds` | 当前模拟时间，单位秒，必须大于等于 `0`             |

主线程命令：

| `type`          | 额外数据                                              |
| --------------- | ----------------------------------------------------- |
| `initialize`    | 初始 `bodies`；固定 `sequence=0`、模拟时间 `0`        |
| `start`         | 无                                                    |
| `pause`         | 无                                                    |
| `step`          | 正数 `stepSeconds`                                    |
| `setTimeScale`  | 正数 `timeScale`，只改变现实时间与模拟时间的推进比例  |
| `replaceBodies` | 完整 `bodies`、预期修订号和快照时间；只允许暂停时提交 |
| `dispose`       | 无                                                    |

Worker 响应：

每条响应都带 `replyToSequence`。直接回执写原命令序号；运行循环产生的后台 `state`、自动降倍率 `status` 和后续碰撞批次写 `null`，因此它们只能通知订阅者，不能提前完成待决 Promise。

| `type`                   | 额外数据                                                                        |
| ------------------------ | ------------------------------------------------------------------------------- |
| `ready`                  | 固定 `sequence=0`、模拟时间 `0`、`replyToSequence=0`、`bodyRevision=0`          |
| `state`                  | 原目标时间、`bodyRevision` 和完整 `PhysicsState`                                |
| `bodiesReplaced`         | 新 `bodyRevision` 和候选实例完整 `PhysicsState`                                 |
| `collisionBatchResolved` | 原目标、接触时间、修订号前后值、事件、账本增量和完整新状态                      |
| `status`                 | `runState` 和 `timeScale`                                                       |
| `error`                  | 错误码、可读消息和 `recoverable`；可关联错误沿用原命令序号，后台错误使用 `null` |
| `disposed`               | 只确认销毁命令                                                                  |

### 物理数据

主要天体包含跨实现共享的数据：`id`、质量、半径、位置、速度、自转角动量、转动惯量因子、由外向内的材料层和碰撞模型。`PhysicsState` 另外保存 tracer、dust cohort、累计碰撞耗散、省略相互作用、累计反作用近似和双层诊断。`activeRebound` 只统计主要天体的 REBOUND 轨道量，`passiveAssets` 单独统计被动资产，避免两种口径混用。

字段名直接写出 SI 单位，避免调用方靠上下文猜单位。协议中没有 Three.js 对象、画面缩放、REBOUND 指针或 Emscripten 内存视图。

`bodyRevision` 表示当前天体集合版本，初始化为 `0`，原子替换或碰撞批次成功后增加 `1`。它与消息 `sequence` 分工明确：修订号保护天体集合，序号保护同一方向的消息顺序。失败操作会消耗消息序号，同时保持修订号不变。

完整天体快照还携带 `expectedSimulationTimeSeconds`。Worker 要求它与当前物理实例时间精确相等，防止运行期间创建的旧位置和旧速度被写到更晚的模拟时刻。所有响应统一使用 `replyToSequence`；直接响应写触发命令的序号，输入无法解析、运行循环帧或定时调度自行失败时为 `null`。

所有数值必须有限。质量必须大于 `0`，半径和模拟时间必须大于等于 `0`，步长必须大于 `0`。时间倍率范围为 `(0, 5400000]`，上限由 `MAX_TIME_SCALE` 导出。同一消息中的天体 `id` 不能重复。主要天体数量限制为 `1..512`，上限由 `MAX_MAJOR_BODY_COUNT` 导出，供协议使用方复用。协议对象使用严格模式，额外字段也会被拒绝。

## 实现细节

### 协议目录

正式协议位于 `src/physics/protocol/`：

- `state-schemas.ts` 定义主要天体、被动资产、累计账本、双层诊断和碰撞事件；`schemas.ts` 组合双向命令与响应，并从 schema 推导 TypeScript 类型。
- `physics-state.ts` 把 REBOUND 动力学快照合并进完整状态，同时保留碰撞产生的被动资产和累计量。
- `parse-message.ts` 接收 `unknown`，分别提供 `parseMainToWorkerMessage` 和 `parseWorkerToMainMessage`。解析失败会抛出 Zod 校验错误，非法数据不能进入物理逻辑。
- `session-sequence-gate.ts` 提供独立的 `SessionSequenceGate`，只负责当前会话和消息顺序。
- 测试覆盖旧版本拒绝、字段缺失、额外字段、非有限数、质量/半径/时间边界、重复资产、握手固定值、512 天体上限、精确回执、碰撞事件与账本对应和完整状态保留。

### 启动握手

启动时序固定如下：

1. 主线程创建 Worker 和一个从未使用过的 `sessionId`。
2. 主线程立即发送 `initialize`，该消息固定为 `sequence=0`、`simulationTimeSeconds=0`，并携带初始天体。
3. Worker 先解析 initialize，再从中取得 sessionId 并建立主线程到 Worker 的顺序门。
4. 物理模块初始化成功后，Worker 发送同 session 的 `ready`，固定为 `sequence=0`、`simulationTimeSeconds=0`。
5. 主线程先解析 ready，再交给预先按该 session 配置的 Worker 到主线程顺序门。
6. 两个方向的后续消息使用严格递增序号。

主线程不会等待一个不带 session 的预 ready。Worker 也不会自行选择 sessionId。这样启动消息和所有后续消息都处于同一版协议与同一会话边界内。

### 解析与顺序

接收端先调用对应解析函数，成功后再把 `sessionId` 和 `sequence` 交给顺序门。顺序门只接受当前 session 中严格大于上次已接收序号的消息；重复、倒退和旧 session 消息都返回明确拒绝原因，且不会推进门状态。序号允许跳跃，便于后续丢弃无需渲染的中间状态。

Worker 重启时，主线程必须生成一个从未使用过的 `sessionId`，再显式调用 `resetForWorkerRestart`。顺序门会记录所有退役 sessionId，并清空新会话的上一序号。旧 Worker 即使稍后送达更大序号，也会因 session 不匹配被拒绝；A 到 B 再回到 A 的复用同样会被拒绝。

主线程到 Worker、Worker 到主线程是两条独立消息流，各自持有一个顺序门，避免双向序号互相干扰。

### 正式 REBOUND 适配层

`src/physics/rebound/` 是产品代码使用 REBOUND 的唯一入口。`emscripten-types.ts` 明确定义固定胶水模块的 12 个 C 导出、句柄和加载参数。`rebound-simulation.ts` 把这些底层函数收进 `ReboundSimulation`：调用方只能初始化天体、推进到绝对模拟时间、读取协议快照和销毁实例。

REBOUND 只返回质量、半径、位置和速度。适配层按稳定粒子顺序保存每颗天体的 ID、材料、自转、惯量和碰撞模型，并在每次快照中深拷贝合并，调用方修改旧快照不会污染后续状态。

浏览器 Worker 通过 Vite 的固定 WASM URL 和 Emscripten `locateFile` 加载 `spikes/rebound-wasm/dist/rebound.wasm`。Node 测试向同一个加载入口提供本地锁定产物路径。适配层不会导出 Emscripten Module、裸指针或原始粒子分量。

初始化固定使用 `G=6.6743e-11` 和 IAS15。`DEFAULT_IAS15_INITIAL_TIMESTEP_SECONDS=3600` 只是 IAS15 的初始步长，后续精度和步长由 IAS15 自适应控制。添加天体后调用 REBOUND 的质心移动。太阳系场景工厂也会先对输入做一次质心化，避免 Worker ready 前后的画面整体跳动。

### 太阳系初始状态

默认场景使用 JPL Horizons 在 `JD 2451545.0 TDB` 的几何向量。查询中心为太阳系质心 `@0`，参考平面为 J2000 黄道面，原始单位为公里和公里每秒。质量通过 Horizons `GM / G` 得到，半径使用目标物理数据中的平均半径。

`solar-system-data.ts` 保存原始数值、查询参数、检索日期和逐目标星历来源；`solar-system.ts` 只负责 SI 换算和质心化。物理协议不会携带中文名、颜色或轨道父级，这些展示数据归档在 `场景与天体目录` 模块。

当前 10 体模型省略其他卫星、小行星和相对论项。它表示“JPL 真实历元初始状态 + REBOUND 牛顿 10 体演化”，不承诺长期逐点复现完整 Horizons 星历。

粒子 ID 按添加顺序保存在 TypeScript 层。快照逐项检查有限数，再恢复协议 `BodyState`。总能量和总角动量来自 REBOUND；总线动量按 `sum(mass * velocity)` 从同一快照计算。`destroy()` 幂等并释放 REBOUND simulation 句柄，Worker 终止后 WASM 模块内存由浏览器回收。

适配器支持 `initialTimeSeconds` 时间原点。底层新 REBOUND 实例仍从本地时间 `0` 开始，对外时间等于“时间原点 + 本地时间”，绝对积分目标会先减去时间原点再交给 WASM。替换后的当前状态不会被重复演化，后续推进仍保持全局模拟时间连续。

### 运行时原子替换

`PhysicsWorkerController.replaceBodies` 在调用入口校验并深拷贝完整天体快照，同时固定草稿创建时记录的 `expectedBodyRevision` 和 `expectedSimulationTimeSeconds`。操作进入独立串行队列并先等待 `pause` 确认。两个基于同一旧修订创建的草稿依次提交时，第一个可以成功，第二个会收到 `bodyRevisionConflict`；运行已推进的旧快照会收到 `bodySnapshotConflict`。

每个 controller 待决请求记录自己发出的命令序号。Worker 可恢复错误通过 `requestSequence` 精确拒绝对应 promise，并发倍率请求、替换请求和主动状态消息不会互相误伤。无法关联到已解析命令的 `null` 错误仍会通知订阅者，同时保留普通待决请求。

Worker 收到命令后执行以下流程：

1. 检查当前已经暂停，并核对 `expectedBodyRevision`。
2. 核对 `expectedSimulationTimeSeconds` 与当前物理时间完全一致。
3. 以旧实例的当前时间为时间原点创建候选 REBOUND 实例。
4. 读取候选首帧，并用协议 schema 校验天体和诊断量。
5. 校验全部成功后切换实例、递增修订号、释放旧实例并发送 `bodiesReplaced`。

候选创建或首帧读取失败会返回可恢复的 `bodyReplacementFailed`，修订冲突返回 `bodyRevisionConflict`，快照时间冲突返回 `bodySnapshotConflict`。这些失败都保留旧实例，用户可以继续单步或用最新快照重新提交。确认响应返回 REBOUND `move_to_com` 后的真实快照，界面不会把未经物理层处理的输入当成正式状态。

`bodiesReplaced` 会无条件把当前诊断设为新的守恒基线。普通 `state` 同时携带修订号；React 合帧逻辑会丢弃旧修订或旧序号的延迟帧，避免替换前最后一帧覆盖新世界。

Task 5 的编辑和删除层直接构造新的完整快照。编辑只替换目标 ID 对应的物理状态；删除拒绝最后一个天体，保证协议的最小数组约束。提交冲突时正式 Worker 继续保留旧实例，界面进入显式冲突状态；用户点击重同步后重新冻结最新修订与时间，再生成候选快照。

### Worker 运行与时间调度

`src/workers/physics.worker.ts` 是正式 module Worker 入口。每个收到的 `unknown` 都先经过 Zod 协议解析，随后进入当前 session 的顺序门。Worker 只接受第一条 `initialize(sequence=0,time=0)` 作为启动消息；REBOUND 成功初始化后才发送 `ready(sequence=0,time=0)`。出站消息由 Worker 独立编号，并带适配层报告的当前模拟时间。

`PhysicsWorkerRuntime` 支持 `start`、`pause`、`step`、`setTimeScale`、`replaceBodies` 和 `dispose`。重复 `start` 是幂等操作，会保持运行和当前调度任务，并返回当前 `running` 状态。协议或积分错误会取消下一次调度并把运行态切到安全暂停，然后发送结构化 `error`。当模拟时间过大、正步长已经小于双精度数能表示的间隔时，单步和连续运行都会明确返回 `integrationFailed`，不会发送未推进的状态。`dispose` 会取消调度、销毁 REBOUND 句柄、发送 `disposed`，最后关闭 Worker。

时间策略使用四个命名常量：

| 常量                                       | 值        | 含义                              |
| ------------------------------------------ | --------- | --------------------------------- |
| `SIMULATION_SECONDS_PER_REAL_SECOND_AT_1X` | `1`       | 1x 时每现实秒推进 1 模拟秒        |
| `PHYSICS_SCHEDULER_INTERVAL_MS`            | `16`      | 两个运行片段之间的最短调度间隔    |
| `MAX_SIMULATION_ADVANCE_PER_SLICE_SECONDS` | `86400`   | 单个同步积分片段最多推进 1 模拟天 |
| `MAX_TIME_SCALE`                           | `5400000` | 协议允许的最大时间倍率            |

每个片段只按本次真实时间差和当前 `timeScale` 计算请求推进量。请求量超过一天时，本片只推进一天，并把当前倍率主动降低为 `86400 / 本次真实间隔秒数`，随后发送包含实际倍率的 `status`。运行时不保存隐形积压，后续片段从已经完成的模拟时间继续计算。暂停命令也先按同一规则结算到暂停瞬间，再取消调度；重新启动不会补跑暂停前未执行的目标。片段结束后使用 `setTimeout` 把控制权交还 Worker 事件循环。时间倍率只参与目标时间计算，不修改 IAS15 初始步长或误差控制。

### 独立轨道预览

`src/physics/preview/` 定义版本 `1` 的一次性预览协议。它与正式协议分开，输入包含完整冻结天体、草稿 ID、可空参考天体、预览时长、采样数量和草稿修订号；输出只包含草稿轨迹、最近中心距离和风险分类。

`orbit-preview.worker.ts` 为每个预览请求创建独立 REBOUND/IAS15 实例，在固定绝对目标时刻读取 256 个展示样本。REBOUND 建模时会移动到新系统质心；预览层保存输入的初始质心位置和速度，并按 `初始位置 + 速度 × 时间` 把输出恢复到输入惯性坐标系。正式 Worker、正式修订号和正式模拟时间不会被修改。

主线程收到结果后，会按原请求校验请求 ID、草稿修订、时长、轨迹 ID 集合、唯一性、点数、严格递增时间、首末时刻和风险引用。Worker 同步构造失败、发送失败、解析失败、积分失败和消息错误都会拒绝 Promise 并清理一次性 Worker；主线程取消时直接终止 Worker。

碰撞预警同时检查初始重叠，并在两个展示点之间最多执行 16 次真实 IAS15 积分，总风险采样封顶 4096，再计算相邻风险样本间的扫掠最近距离和首次接触时刻。额外细分使用天体数量加权预算，接近 512 体时降到每段一次，避免大系统承担固定 16 倍快照成本。逃逸预警使用末端相对参考天体的二体比能与径向速度。两者都是短期风险分类，不执行 M3 的碰撞结果，也不改变 IAS15 的正式积分配置。有限采样无法数学保证捕获所有极端弯入再弯出事件，连续碰撞事件检测留到 M3。

`referenceBodyId=null` 表示当前没有可用参考天体。预览仍运行完整多体积分并输出草稿轨迹，碰撞风险也照常计算；逃逸风险依赖二体参考系，因此无参考请求跳过该分类。协议响应校验会拒绝无参考请求返回的 `escape`，避免错误风险进入界面。只剩一个天体时没有碰撞配对，轨迹照常输出，`closestApproachMeters` 返回 `null`。

### 主线程 controller 和工程探针

`PhysicsWorkerController` 生成 session、构造严格递增的命令、解析并过滤 Worker 响应，同时提供 initialize、启动、暂停、单步、倍率和销毁方法。初始化成功前的运行命令会立即拒绝。浏览器 Worker `error`、`messageerror`、无法解析的响应、15 秒操作超时和不可恢复的 Worker 错误会拒绝等待中的操作并终止 Worker；可恢复的 Worker 错误只拒绝当前等待操作，保留 controller 供用户继续控制。终止路径会移除监听器和计时器。

`probePhysicsWorker` 是保留的工程探针，不进入正式页面。它创建正式 Worker，初始化真实 SI 太阳地球场景，等待 ready，依次发送 start、pause、单步推进 3600 秒，检查 state 后发送 dispose。它取代了只返回固定字符串的 foundation Worker 探针。

### Collision WASM 固定内核

`crates/stary-collision/` 保存固定 Rust 工具链、源码、锁文件、生成产物和验证脚本：

- `rust-toolchain.toml`、`Cargo.toml` 和 `Cargo.lock` 固定编译器、目标与依赖。
- `scripts/build.ps1` 使用锁定 Docker 镜像生成唯一 `dist/stary_collision.wasm`；仓库命令为 `pnpm build:collision-wasm`。
- `scripts/verify.ps1` 在固定容器中重建并运行 Rust release 测试，再检查产物哈希和 ABI；仓库命令为 `pnpm verify:collision-wasm`。
- `pnpm check:collision-wasm` 只检查当前产物、完整输入哈希、导出白名单和 token 生命周期，供 `pnpm build` 快速使用。
- `artifact-lock.json` 锁定 Rust/Cargo 版本、目标、容器摘要、源码与脚本输入，以及唯一 WASM 的字节数和 SHA-256。
- Release 配置使用 `panic=abort`、整数溢出检查、fat LTO、单 codegen unit 和 strip，未启用 fast-math 或 `wasm-bindgen`。

### REBOUND/WASM 原型

`spikes/rebound-wasm/` 保存固定上游输入、桥接源码、生成产物和原型验收，职责是提供可重复构建的物理二进制：

- `source-lock.json` 固定 REBOUND 源码和 Emscripten 镜像。
- `scripts/` 下载并校验源码，在固定容器中生成 `.mjs` 和 `.wasm`。
- `src/rebound_bridge.c` 暴露最小 C 接口。
- `web/rebound-client.mjs` 提供原型 JavaScript 适配。
- `web/physics-worker.mjs` 和静态页面验证浏览器 Worker 加载。
- `scripts/static-server.mjs` 为验收页提供正确的模块与 WASM MIME，并限制可访问目录。
- `artifact-lock.json` 和 `scripts/verify.ps1` 保证固定输入重建后的补丁与 WASM 产物哈希一致。
- `web/sun-earth-scenario.mjs` 固定太阳-地球质心场景、解析周期和验收容差。

REBOUND 的原始 Emscripten 路径会在较长的单次积分中调用 `emscripten_sleep(0)`，用于上游网页显示刷新。当前构建没有使用 `ASYNCIFY`，并应用固定补丁禁用这一个 120Hz 显示让出调用。物理运行在专用 Worker；正式线程必须把异步分片推进作为 JavaScript 调度职责，并在片段之间让出事件循环。

`web/` 下的原型客户端和场景没有进入产品导入图。正式代码只引用锁定的 `.mjs`、`.wasm` 和产品内 TypeScript 类型适配层。
