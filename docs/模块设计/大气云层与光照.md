# 大气云层与光照

## 当前状态

M2 Task 3 已完成。地球、金星和火星拥有独立大气边缘；地球拥有真实云层、方向性云影和程序化回退；恒星遮挡会影响地表明暗与曝光；土星环影会随恒星方向改变强度和落点。

## 设计

### 职责与结构

- `appearance/body-environment.ts` 保存固定天体的大气和云层纯数据参数，并按模拟时间计算云相位。
- `visuals/body-environment.ts` 创建、更新和释放大气球壳、云层、云影与程序化云图。
- `lighting/stellar-occlusion.ts` 从 SI 位置和半径计算恒星圆盘可见比例。
- `adaptive-exposure.ts` 计算观察目标曝光，并按帧时间平滑逼近。
- `visuals/planetary-ring.ts` 管土星实体环和局部环影。
- `observatory-scene.ts` 只负责把物理快照、相机、灯光观察结果和视觉资源串起来。

物理 Worker 不读取这些模块。大气、云层、阴影和曝光只改变画面，不会修改质量、半径、位置、速度、时间或积分结果。

### 大气

地球、金星和火星各使用两层 `MeshBasicMaterial` 背面球壳。球壳略大于真实表面，关闭深度写入并保留深度测试。行星实体会挡住球壳中心，只留下随轮廓自然增厚的边缘。

- 地球：`1.012R` 与 `1.026R`，蓝色。
- 金星：`1.016R` 与 `1.035R`，淡黄色。
- 火星：`1.008R` 与 `1.016R`，低透明暖色。

投影半径小于 `5px` 时关闭大气，避免远景透明层浪费。当前方案稳定覆盖 WebGPU 与 WebGL2，属于轮廓近似。完整 Rayleigh/Mie 散射需要自定义节点材质和双后端单独验收。

### 云层与云影

地球云层位于 `1.008R`，使用 `MeshStandardMaterial` 和本地灰度透明度图。云影位于 `1.0015R`，与云层共享同一个纹理租约。投影半径小于 `12px` 时两者关闭；URL 参数 `cloudShadows=0` 可以关闭云影，用于质量降级和对照排障。

云相位只由 `bodySnapshotSimulationTimeSeconds` 计算。相对地表完整转动周期为 432,000 模拟秒，也就是 5 个模拟日。暂停后快照时间稳定，云层保持不动；单步和倍率通过同一模拟时间路径推进。渲染帧不会自行累加云角度，因此相同快照始终得到相同画面。

云影先继承云相位，再根据主导恒星方向施加小角度球面旋转。观测到的受光比例或恒星可见比例接近零时，云影透明度降为零并隐藏。这个方法能表达方向和昼夜变化，计算成本稳定；局部软阴影形状仍是近似。

真实云图失败时使用稳定种子生成 `256×128` 程序化透明度图。程序化图包含透明和不透明结构，继续参与模拟时间运动与云影。资产生命周期记录在 `docs/模块设计/天体画面资产.md`。

### 恒星照明与食相

场景最多保留四颗质量最大的恒星 PointLight，同质量按 ID 排序。每个需要环境、环影或聚焦诊断的目标天体会选择当前照度最大的恒星，记录方向、照度、受光相位、遮挡体和恒星可见比例。

单个遮挡体使用两个角圆盘的解析重叠面积。多个遮挡体可能覆盖恒星圆盘同一区域，因此使用固定 1024 点的确定性圆盘采样求联合遮挡；重叠区域只计算一次。采样只发生在存在多个有效遮挡体时，常见无遮挡和单遮挡路径保持常数成本。

所有活跃恒星会分别计算遮挡前后照度。两者总和的比例会压低目标天体 `MeshStandardMaterial` 的地表颜色系数，让全局 PointLight 下的该天体同步变暗；未被遮挡的次星贡献会保留。大气透明度、云影和曝光使用同一比例，阴影方向使用遮挡后照度最大的主导恒星。内置材质无法为每个目标单独屏蔽某一盏 PointLight，这里采用每目标颜色系数近似直射光衰减。

### 土星环影

环影使用贴近土星表面的透明球面和程序化纬向透明度图。环面法线与恒星方向的点积决定投影：恒星沿环面照射时投影面积接近零，正对环面时环内洞完整落在行星圆盘外，这两个极端都关闭环影；环带投影跨过行星圆盘的中间角度最深。带符号点积同时移动透明度图的纬向偏移，恒星跨越环面后暗带移动到另一侧。

该方案避免开启 PointLight 的六面立方阴影图。太阳系显示尺度下，全场景阴影图难以同时覆盖天文距离与行星半径，四盏恒星灯还会带来最多 24 次额外阴影渲染。当前局部环影更稳定，完整环粒子投影可以在专用材质阶段升级。

### 曝光

全景曝光固定为 `1.1`。恒星近景目标为 `0.68`；普通天体根据受光相位和恒星可见比例在 `1.02..1.34` 之间调整；黑洞目标上限为 `1.38`。

每帧使用真实时间差进行指数平滑。变暗时间常数为 `0.35s`，变亮时间常数为 `1.4s`，单帧时间差最多按 `0.25s` 处理。这样从恒星切到暗面时保留多个中间值，不会闪跳或越过目标。曝光只影响 Three.js 画布，HTML 界面保持原亮度。

### 诊断与释放

`visualDiagnostics=1` 提供大气层数与外半径、云资产状态与相位、云影可见性、环影透明度与纬向偏移、当前与目标曝光、主导恒星、受光比例、遮挡体和资源数量。诊断每 100 毫秒最多更新一次，默认访问没有序列化开销。

`BodyVisual` 拥有环境 Group、球体几何、大气材质、云材质、云影材质和程序化云图。云真实纹理由 `BodyVisualAssetBinding` 的租约拥有。销毁时先取消加载并释放租约，再释放环境材质、几何和程序化纹理；场景缓存最后兜底释放剩余资源。

## 实现细节

1. 物理快照更新时，场景把绝对模拟时间传给环境资源。
2. 渲染帧根据相机计算真实球体投影半径，选择环境可见性和 LOD。
3. 场景从当前 SI 状态计算目标天体的主导恒星与联合遮挡。
4. 同一观察结果更新地表明暗、大气、云影、环影和曝光目标。
5. 云纹理在聚焦或进入 medium LOD 时与表面一起按需加载。
6. 低频诊断把资源状态与投影数据暴露给浏览器验收。

WebGPU 与 WebGL2 共用 Three.js 内置材质和同一份物理观察结果。WebGL2 只减少球体分段，不移除大气、云层、云影、环影或曝光。

## 验证

- 纯函数测试覆盖三颗行星参数、云相位周期与大时间取模、曝光上下限与快暗慢亮、解析圆盘重叠和多个遮挡体联合区域。
- 资源测试覆盖双层大气、云和云影创建，方向变化、夜面隐藏、投影阈值、无效光照输入和完整释放。
- BodyVisual 测试覆盖食相可见比例对非恒星地表明暗的影响，以及真实云纹理绑定、失败、取消和迟到释放。
- 土星环测试覆盖真实环比例、径向 UV、迎光强度、恒星跨面后的阴影偏移、沿环面关闭和资源释放。
- Playwright 在桌面默认后端与手机强制 WebGL2 下检查蓝色大气边缘、海陆纹理、真实云和土星实体环的画布像素，并通过诊断确认云影与环影状态；两条流程均要求零 console warning/error。
- 暂停后云相位与画面冻结；单步一小时后相位推进 `π/60`，球内像素变化且构图稳定。
- 云图错误 MIME 时程序化云继续可见、可移动；太阳切换到地球时曝光单调经过多个中间值并最终收敛。
