# 工程底座

## 设计

### 职责

工程底座负责把浏览器应用、模块 Worker、WebAssembly 资源和 Three.js 两条渲染路径交给同一套可重复的构建流程。它同时提供格式检查、静态检查、严格类型、单元测试、生产构建和浏览器验收门禁。

正式应用已经由工程探针页演进为太阳系多体观测台。物理消息协议与 controller 由物理核心实现，场景数据由 `场景与天体目录` 模块归档，画面和交互由 `画面与交互` 模块实现。

### 目录结构

| 位置                        | 职责                                            |
| --------------------------- | ----------------------------------------------- |
| `src/app/`                  | 正式 React 应用入口和全局基础样式               |
| `src/features/observatory/` | 观测台状态、组件、Three.js 场景和响应式样式     |
| `src/platform/probes/`      | 三类运行时探针共用的状态和错误描述              |
| `src/platform/rendering/`   | 浏览器渲染适配器、回退和 Three.js 模块探针      |
| `src/platform/wasm/`        | 固定 REBOUND WASM 的资源 URL 与浏览器编译探针   |
| `src/physics/controller/`   | 正式物理 Worker 创建、命令、超时、错误和清理    |
| `src/workers/`              | 正式物理 module Worker 入口                     |
| `scripts/verify-build.mjs`  | 检查生产构建的资源、哈希、渲染模块和 source map |

### 关键决策

- 运行时固定为 Node.js `22.14.0`，包管理器固定为 pnpm `10.21.0`。版本同时写入 `.nvmrc`、`package.json` 和锁文件。
- 应用使用 React `19.2.7`、Vite `8.1.4`、Three.js `0.185.1`。依赖全部使用精确版本，减少不同机器上安装结果漂移。
- TypeScript 固定为 `6.0.3`。安装时验证过 TypeScript 7 已超出 `typescript-eslint 8.64.0` 的支持范围，当前组合没有 peer dependency 警告。
- TypeScript 应用配置和 Node 构建配置都开启 `strict`，并额外开启未使用代码、数组越界提示、精确可选属性和未检查副作用导入等检查。
- WebGPU 和 WebGL2 模块使用动态导入。WebGPU 路径需要 `navigator.gpu.requestAdapter()` 返回适配器且模块导入成功；任一步失败都会尝试 WebGL2。浏览器只加载最终选中的渲染后端，生产构建仍会验证两条路径都能生成。
- REBOUND WASM 通过 Vite `?url` 导入。构建关闭小资源内联，因此 `.wasm` 保持为独立文件。临时页面只有在请求成功、MIME 为 `application/wasm` 且 `WebAssembly.compileStreaming` 成功后才显示就绪。
- 生产构建关闭 source map，避免发布源码映射。构建脚本会再次扫描产物，防止配置回退后静默泄露。

## 实现细节

### 工具链和门禁

`package.json` 的主要命令如下：

| 命令                    | 检查内容                                                        |
| ----------------------- | --------------------------------------------------------------- |
| `pnpm format:check`     | 检查当前应用、配置、构建脚本和本模块文档格式                    |
| `pnpm lint`             | 对 TypeScript、TSX、构建配置和 Node 脚本执行零 warning 静态检查 |
| `pnpm typecheck`        | 用 TypeScript project references 检查浏览器代码和 Node 配置     |
| `pnpm test`             | 在 Node 环境运行物理、状态、坐标、轨道和格式化测试              |
| `pnpm build`            | 先做类型检查，再生产构建，最后检查实际产物                      |
| `pnpm test:e2e`         | 构建后运行桌面、手机和 WebGL2 回退浏览器验收                    |
| `pnpm test:performance` | 构建后采样 2 秒 RAF 和 Worker state 序号推进频率                |
| `pnpm check`            | 按顺序执行上述全部门禁并追加 Playwright 浏览器验收              |

`tsconfig.app.json` 管浏览器代码，`tsconfig.node.json` 管 Vite 配置，`tsconfig.e2e.json` 管 Playwright 验收。配置分开后，DOM 全局类型不会混入 Node 构建环境。

ESLint 使用类型感知规则。大白话说，它会结合 TypeScript 推断结果检查代码，能发现只看文本时看不到的错误 Promise 和不安全类型使用。

### 渲染能力

`probeRenderingPath` 先实际调用 `navigator.gpu.requestAdapter()`。取得适配器后继续导入 `three/webgpu`。适配器返回 `null`、调用抛错或模块导入失败都会进入 WebGL2 回退。回退路径先创建 `webgl2` 上下文，再导入 `three`；上下文或模块失败时才把探针标为错误。

两套 Three.js 模块和观测场景保持动态导入。这会让 Vite 生成独立代码块，避免首屏立即下载两套渲染器。正式观测台先创建 WebGPU 渲染器并等待初始化；失败后创建明确使用 `webgl2` 上下文的 WebGLRenderer。

测试覆盖 WebGPU 成功、适配器为 `null`、适配器抛错、WebGPU 模块失败、WebGL2 上下文缺失和 WebGL2 模块失败。

### Worker 和 WASM

`createPhysicsWorker` 使用 `new Worker(new URL(..., import.meta.url), { type: 'module' })`。Vite 因此把正式物理 Worker 和固定 Emscripten 胶水编译到独立 ES module 文件。旧的固定 ready 字符串 Worker 已删除。

`probePhysicsWorker` 通过正式 controller 初始化真实太阳地球场景，等待 ready，依次启动、暂停、单步推进 3600 秒并销毁。controller 同时监听 `message`、`error` 和 `messageerror`，每次操作有 15 秒超时。成功、错误、超时和页面卸载都会移除全部监听、清除计时器并终止 Worker。

`REBOUND_WASM_URL` 指向 Task 1 固定构建的 `spikes/rebound-wasm/dist/rebound.wasm`。`probeReboundWasm` 用 `fetch` 读取该 URL，检查 HTTP 状态与 MIME，再把响应交给 `WebAssembly.compileStreaming`。测试会真实编译一个最小合法 WASM，并覆盖 HTTP、MIME 和坏二进制错误。

### 生产产物检查

`verify-build.mjs` 递归读取 `dist/` 并执行以下检查：

1. 不存在 `.map` 文件。
2. 恰好存在一个正式 physics Worker，不再包含 foundation Worker，并且全包只有一个 REBOUND `.wasm`。
3. 固定 Emscripten 胶水源文件、原始 WASM 和发布 WASM 的字节数、SHA-256 都与 `artifact-lock.json` 一致。
4. 正式 Worker 包含 REBOUND 创建和积分导出，并引用唯一发布 WASM 的哈希文件名，证明胶水和二进制都进入产品构建图。
5. Vite manifest 同时记录 Three.js WebGPU、WebGL 和观测场景三个动态入口，首屏主包不提前加载完整画面引擎。
6. 输出每个文件的原始字节数、gzip 字节数和总量，便于持续观察包体积。

### 正式应用入口

`App.tsx` 组合全屏画布、顶栏、天体目录、只读数据面板、手机抽屉和时间控制。`StrictMode` 已开启，状态 Hook 会在重复挂载、重试和卸载时关闭旧 Worker、取消订阅与动画帧。

展示层没有外观单测。状态映射、显示换算、坐标比例、相机适配、轨道采样和浏览器工作流分别由纯函数测试与 Playwright 验收覆盖。

`e2e/observatory-performance.spec.ts` 等待正式 Worker 运行并收到首个 state，然后采样至少 2 秒。它输出浏览器版本、视口、渲染后端、RAF 频率和 Worker state 序号推进频率。Playwright 配置负责启动并关闭生产预览，不留下常驻开发服务器。该命令始终测当前默认场景；历史 M0 环境、双天体生产包和固定样本见 `docs/2026-07-14-stary-m0-acceptance.md`。

### 2026-07-14：工程探针切换到正式物理 Worker

- 删除只发送固定字符串的 foundation Worker 和对应探针。

### 2026-07-14：收紧浏览器运行时探针

- 生产构建改为按 `artifact-lock.json` 同时约束源 WASM 和发布 WASM。
