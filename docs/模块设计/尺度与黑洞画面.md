# 尺度与黑洞画面

## 当前状态

M2 已完成。用户可以从太阳系全景平滑进入普通天体表面和黑洞近景，运行中的 Worker 快照不会重置已经调整过的镜头。桌面默认后端与手机 WebGL2 都能辨认黑洞暗核和光子环，正式性能与共享纹理生命周期也已通过重复验收。

## 设计

### 职责与结构

- `coordinates.ts` 负责 SI 位置、场景比例、移动渲染原点和相机坐标重投影。
- `camera-focus.ts` 负责全景、父子轨道构图、真实半径近景和黑洞外轮廓构图。
- `camera-navigation.ts` 负责过渡时间、对数距离、交互速度和 near/far。
- `appearance/black-hole-appearance.ts` 只保存黑洞物理比例，不创建 Three.js 对象。
- `visuals/black-hole.ts` 创建、缩放、隐藏和释放黑洞暗核、光子环与光晕。
- `observatory-scene.ts` 编排焦点、原点、相机、星空、诊断和资源生命周期。
- `UniverseViewport.tsx` 保存场景尚未拥有新天体时的单次聚焦意图。

物理 Worker 仍是唯一状态来源。画面模块不会修改质量、半径、位置、速度、模拟时间或守恒诊断。

### 真实比例与近似

黑洞创建预设把 `radiusMeters` 设为 Schwarzschild 半径 `Rs = 2GM/c²`。正式物理球继续使用 `1 Rs`，并保持黑色、非发光和可参与牛顿多体引力。

可观察画面采用以下比例：

| 结构           |                    半径 | 用途                           |
| -------------- | ----------------------: | ------------------------------ |
| 事件视界物理球 |                  `1 Rs` | 保留创建参数和真实物理半径     |
| 光子球轨道     |                `1.5 Rs` | 记录理论参考，不单独绘制实体壳 |
| 黑洞阴影       | `3√3 / 2 Rs ≈ 2.598 Rs` | 观察者看到的主要暗核边界       |
| 光子环         | `3√3 / 2 Rs ≈ 2.598 Rs` | 冷白窄环，宽度只做可见性增强   |
| 可观察外轮廓   |               `3.25 Rs` | 包含光子环和 WebGPU 冷色光晕   |

这里的“阴影”大于事件视界，因为强引力会让靠近黑洞的光线被捕获。首版 N 体运动仍使用 REBOUND 的牛顿引力，没有计算广义相对论轨道修正、黑洞内部或全屏光线追踪。

当前 `BodyState` 没有气体、尘埃、碎屑密度和角动量方向，因此 `accretionDisk` 固定为 `null`。附近存在普通行星也不会自动生成吸积盘。

### 双后端画面

暗核和光子环合并在一张 `256×256` 程序化 DataTexture 中，由始终朝向相机的 Sprite 绘制。中心保持接近不透明黑色，环带使用冷白到浅蓝颜色，并加入轻微角向亮度差。相同参数的黑洞共享纹理和引用计数，每颗天体只拥有自己的 Sprite 与材质。

WebGPU 再增加一个 AdditiveBlending Sprite，表现可观察边界外的冷色透镜光晕。WebGL2 不创建这个额外资源，仍保留暗核和光子环。两个 Sprite 都参与深度测试，并在定位环和创建草稿之前绘制，前景天体和交互标记可以正常遮挡黑洞。投影半径低于 `4px` 时隐藏增强层，远景继续依靠定位环选择。

完整背景扭曲需要额外渲染目标、全场景采样和双后端 Shader。Task 4 没有引入这套后处理，避免把未经验证的第二次场景绘制和显存开销带入正式路径。

## 实现细节

### 移动渲染原点

全景以 SI 零点为原点。聚焦天体后，场景把该天体最新 SI 位置设为渲染原点。天体、轨道、定位环、创建草稿和预览轨迹都在 CPU 端先减原点，再乘 `metersToSceneUnit` 写入 Three.js。

同一个焦点随模拟移动时，相机、OrbitControls target 和未完成过渡保留本地坐标，只更新原点对应的 SI 位置。这样相机等同于和天体一起移动。切换到另一个焦点或返回全景时，代码先把旧场景坐标还原成 SI 世界位置，再投影到新原点，画面起点不会跳变。

若系统物理范围触发重新标定，同一移动原点下的本地坐标和相机距离按新旧比例同比缩放。全景和创建镜头使用固定显示构图，不跟随场景比例放大或缩小。

### 相机与尺度

焦点切换保存当前观察方向。控制中心在起点和终点间线性移动，距离在对数空间插值，再使用平滑曲线控制速度。大跨度切换限制在 `420..960ms`，从行星全景进入公里级黑洞近景也不会一帧闪现。

`system`、`orbit`、`surface` 负责 LOD、诊断和范围选择。交互速度直接读取聚焦天体投影半径，在对数空间从系统档连续过渡到表面档，所以跨阈值时没有滚轮突变。

near 对三档使用同一公式：取当前距离的千分之一与“镜头到可观察外轮廓空隙”的四分之一中较小值，并保留 `1e-12` 下限。最小距离停在外轮廓的 `1.03` 倍之外。far 按近景、轨道区和系统范围分档，星空跟随相机并使用当前 far 调整尺寸。

### React 与创建模式

普通 Worker 快照只调用 `scene.update()`。场景在过渡结束后平移相机和控制中心跟随焦点，不会再次执行 `focusBody()`，所以用户滚轮和旋转保持不变。

创建确认存在一帧时序差：焦点 ID 可能先于替换后的 bodies 到达 React。`UniverseViewport` 只在 `focusBody()` 返回失败时保存目标 ID，下一批 bodies 更新后重试；成功、切到全景或换目标都会清除旧意图。

进入创建俯视镜头时同时保存场景比例。创建期间新增天体若改变系统范围，退出时对旧聚焦相机位置、控制中心和距离应用比例换算，再重新计算导航裁剪范围。

### 资源与诊断

黑洞 Sprite 与材质归 `BodyVisual` 所有，程序化纹理由模块共享引用。删除天体、外观结构变化和场景销毁都会幂等释放材质并归还纹理引用，最后一个引用离开时才释放 DataTexture；WebGPU 光晕按同一路径管理。资源诊断同时记录共享纹理池的 entry 和 reference，视口失败、重建与销毁可以直接证明引用回到稳定平台。

`visualDiagnostics=1` 提供：

- 相机距离、near/far、最小/最大距离、旋转与滚轮速度、过渡进度和终点。
- 当前渲染原点天体、焦点本地位置和最大本地坐标。
- 最近尺度切换历史。
- 黑洞后端模式、暗核/光晕可见性、物理与可观察投影半径、吸积盘状态。
- 可释放资源数量和纹理缓存状态。

## 验证

- 坐标单测覆盖远处小位移、同焦点移动、尺度变化和原点身份切换。
- 相机单测覆盖对数距离、过渡时间、平滑速度、连续 near 和有效裁剪范围。
- 创建相机单测覆盖保存、精确恢复和场景比例变化。
- 黑洞单测覆盖固定比例、暗核/亮环纹理、WebGPU/WebGL2 组成、投影缩放、可见阈值和幂等释放。
- Playwright 覆盖运行中聚焦终点不漂移、滚轮缩放跨 Worker 快照保持、返回全景、创建后待处理焦点、尺度历史和资源稳定平台。
- 黑洞画布验收按诊断投影中心采样暗核、亮环、冷色倾向与角向覆盖；桌面默认后端和 `390×844` 手机 WebGL2 使用相同结构标准。
- 完整门禁通过 46 个 Vitest 文件、322 项测试和 23 条 Playwright；生产包为 `2,683,906` 原始字节、`1,256,973` gzip 字节。

## 已知边界

- 当前没有吸积盘、喷流和全屏背景扭曲。
- 黑洞动力学使用牛顿多体引力，事件视界与光子环只用于半径和画面表达。
- 程序化 Sprite 是可审计近似，不能替代广义相对论光线追踪。
- 正式五秒重复矩阵已覆盖桌面 WebGPU 与桌面、手机 WebGL2。更多设备、512 个主要天体和大量黑洞压力测试进入 M5；共享纹理已经避免黑洞数量线性放大程序化纹理内存。
