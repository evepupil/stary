## 设计

### 职责

- `src/history/` 保存快照模型、规范化序列化、完整性校验与(后续任务的)时间线树,纯 TypeScript,不接触 DOM 与 IndexedDB。
- `src/physics/protocol/` 与 `src/physics/runtime/`(Task 2)负责协议 v4 的完整状态恢复。
- `src/platform/storage/`(Task 4)负责 IndexedDB 与内存适配器。
- `src/features/archive/`(Task 5/6)负责时间轴与导入导出界面。

### 快照格式 v1

| 字段                         | 说明                                                   |
| ---------------------------- | ------------------------------------------------------ |
| `format`                     | 固定 `stary-snapshot`                                  |
| `formatVersion`              | 固定 `1`                                               |
| `snapshotId`                 | `snapshot-<内容哈希>`,由内容派生,改元数据不改身份      |
| `label`                      | 可空标签,最长 120 字符                                 |
| `capturedAtUnixMilliseconds` | 创建墙钟毫秒;元数据,不进哈希                           |
| `simulationTimeSeconds`      | 快照时刻,非负有限                                      |
| `bodyRevision`               | 捕获时修订号                                           |
| `timeScale`                  | 捕获时时间倍率,`(0, 5_400_000]`                        |
| `physicsState`               | 协议 v3 完整状态(严格 schema,含被动资产与累计账本)     |
| `contentHash`                | 16 位十六进制 FNV-1a 64,覆盖除元数据外的全部可恢复内容 |

规范化 JSON 规则:对象键按 UTF-16 码元升序、数组保序、数值用 JSON 最短往返表示(`-0` 归一为 `0`)、禁止非有限数。内容哈希与快照 ID 都在规范化字符串上计算,同一内容在任何平台得到同一哈希。

### 编解码与错误

`createStarySnapshot` 校验内容、计算哈希并生成快照;`encodeStarySnapshotToJson` 输出规范化 JSON(可直接落盘或分享);`decodeStarySnapshotFromJson` 依次执行大小上限、JSON 解析、格式与版本检查、严格 schema、哈希复验,错误以 `SnapshotCodecError` 抛出,代码为:

`snapshotTooLarge`、`invalidJson`、`unsupportedFormat`、`unsupportedVersion`、`malformedSnapshot`、`contentHashMismatch`。

解码入口默认上限 64 MiB;对象数量与数值范围由协议 schema 的既有上限(512 主要天体、10,000 被动资产)直接复用。

## 已知边界

- `-0` 在序列化时归一为 `0`;两者物理等价。
- 跨浏览器回放只承诺数值容差内一致;逐位一致只在同构建同平台成立(M3 Task 7 已在 Node 证实)。
- 首版存储全量快照,不做差异压缩。
- 逐命令操作日志与命令级重放暂缓。
