## 当前状态

M3 Task 2 已为固定太阳系补齐碰撞物理资料。默认场景仍包含太阳、八大行星和月球，共 10 个主要天体；位置和速度来自固定 J2000 历元，材料、自转角动量、转动惯量因子和碰撞模型来自独立的版本内静态资料。目录继续提供稳定 ID、类别、颜色、轨道父级和选择顺序，渲染层再按稳定 ID 关联本地画面资产。

## 设计

### 职责边界

- `src/physics/scenarios/` 保存可进入物理线程的纯 SI 初始状态。
- `src/features/observatory/catalog/` 保存中文名、类别、显示色、顺序、分组和轨道父级。
- `BodyState` 保存 ID、质量、半径、位置、速度，以及碰撞所需的材料层、自转角动量、转动惯量因子和碰撞模型。展示文字和颜色不会进入物理协议。

这条边界让物理数据可以独立验证，也避免为了增加名称或颜色升级 Worker 协议。

### 默认太阳系

固定历元为 J2000，即 `JD 2451545.0 TDB`。位置和速度通过 JPL Horizons 查询，参考中心为太阳系质心 `@0`，参考平面为 J2000 黄道面，输出单位为 `KM-S`，应用启动时统一转换成米和米每秒。

数据查询参数和每个目标的星历来源保存在 `solar-system-data.ts`。中心来源为 DE441；太阳、水星、金星、地球和月球使用 DE441，火星及外行星使用 Horizons 响应列出的目标星历文件。官方接口说明为 `https://ssd-api.jpl.nasa.gov/doc/horizons.html`，本次静态数据检索日期为 2026-07-14。

质量通过 JPL `GM * 10^9 / G` 换算成千克，`G=6.6743e-11 m^3 kg^-1 s^-2`。平均半径从公里转换成米。场景工厂随后计算当前 10 体模型自己的质心位置与速度，并从每个天体状态中减去，避免 Worker 首帧整体跳动。REBOUND 初始化时仍会再次调用 `move_to_com` 作为防线。

这个模型使用真实历元初始状态和牛顿 10 体演化。完整 JPL 模型还包含其他卫星、小行星和相对论修正，因此长时间结果不会与 Horizons 星历逐点重合。

### 固定碰撞物理资料

`solar-system-physical-profiles.ts` 按固定 ID 保存 10 体资料。材料层由外到内排列，太阳使用 `stellar`，五个岩质天体使用 `gravitySolid`，四个巨行星使用 `gravityFluid`。

| 天体   | 碰撞模型       | 材料质量分数                                 | `I / MR²` |
| ------ | -------------- | -------------------------------------------- | --------- |
| 太阳   | `stellar`      | gas 1.00                                     | 0.0700    |
| 水星   | `gravitySolid` | silicate 0.30, iron 0.70                     | 0.3460    |
| 金星   | `gravitySolid` | silicate 0.68, iron 0.32                     | 0.3370    |
| 地球   | `gravitySolid` | silicate 0.675, iron 0.325                   | 0.3307    |
| 月球   | `gravitySolid` | silicate 0.98, iron 0.02                     | 0.3930    |
| 火星   | `gravitySolid` | silicate 0.78, iron 0.22                     | 0.3660    |
| 木星   | `gravityFluid` | gas 0.90, ice 0.06, silicate 0.03, iron 0.01 | 0.2540    |
| 土星   | `gravityFluid` | gas 0.75, ice 0.15, silicate 0.07, iron 0.03 | 0.2100    |
| 天王星 | `gravityFluid` | gas 0.15, ice 0.65, silicate 0.14, iron 0.06 | 0.2250    |
| 海王星 | `gravityFluid` | gas 0.15, ice 0.65, silicate 0.14, iron 0.06 | 0.2300    |

自转角动量使用 `L = k M R² 2π/P`。自转周期参考 JPL Solar System Dynamics 的 [Planetary Physical Parameters](https://ssd.jpl.nasa.gov/planets/phys_par.html)，本项目记录的检索日期为 2026-07-16；自转极点使用 Archinal 等人的 IAU 2015 旋转要素，DOI 为 `10.1007/s10569-017-9805-5`，并从赤道 J2000 转到当前场景的 J2000 黄道坐标。代码同时保存逐体周期和黄道单位轴，测试会独立重算 `L` 的模长与方向。金星和天王星按负旋转方向处理，因此角动量的黄道 `z` 分量为负。太阳差速自转被压成一个刚体周期，月球与巨行星也只保留单一整体自转，这是当前碰撞账本的刚体近似。

四类材料是碰撞剥离用的账本桶。岩质天体的核幔比例参考公开内部结构结果；木星参考 Juno 重力约束，DOI 为 `10.1002/2017GL073160`；土星参考环震学约束，DOI 为 `10.1038/s41550-021-01448-3`；天王星和海王星参考 Helled、Nettelmann 与 Guillot 的综述，DOI 为 `10.1007/s11214-020-00660-3`。具体分数是 STARY 将宽范围内部结构压缩到 gas、ice、silicate、iron 四层后的确定性近似。这里的 `ice` 表示高压水、氨和甲烷等挥发物总类，不表示常温表面冰；低质量大气、海洋和未建模微量成分并入主体层。资料用于可重复的材料去向和守恒计算，不宣称复现每颗行星的唯一内部模型。

### 展示目录

目录固定顺序为太阳、水星、金星、地球、月球、火星、木星、土星、天王星和海王星。界面按恒星、内行星、外行星和卫星分组，月球的 `orbitParentId` 为地球，其余行星的父级为太阳。

未知 ID 仍可进入物理和画面。它会落到“其他”分组，使用通用名称、颜色和最大质量天体作为轨道父级，避免未来用户创建的天体因为缺少静态目录而消失。

### 视觉分类边界

目录只保存业务稳定的名称、类别、颜色和父级，不保存 Three.js 材质、纹理或 GPU 资源。`rendering/appearance/body-appearance.ts` 结合目录和稳定创建 ID，把天体解析为恒星、岩石、气态巨行星、冰巨行星、无气层或黑洞六类表面。

水星和月球使用无气层外观；金星、地球和火星使用岩石外观；木星、土星使用气态巨行星外观；天王星、海王星使用冰巨行星外观。太阳和动态创建恒星的颜色与灯光参数由质量和半径推导，动态创建天体继续从 ID 恢复类别。未知 ID 使用确定性的无气层回退。

固定目录 ID 通过 `rendering/assets/body-asset-plan.ts` 映射到本地表面资产。这个映射留在渲染层，目录仍不持有 URL、许可或 GPU 对象。动态创建和未知 ID 没有固定贴图计划，继续使用稳定种子生成的类别外观。

太阳、八大行星、月球和土星环统一来自 Solar System Scope / INOVE，许可为 CC BY 4.0。原图与成品哈希、处理方法和逐资产 URL 记录在 `planetary-assets.json`，详细运行时设计归档在 `docs/模块设计/天体画面资产.md`。这些贴图基于 NASA 数据制作，成品仍需保留发布者署名。

## 实现细节

### 数据生成

- `constants.ts` 集中保存引力常数、公里换算、儒略日和天文单位。
- `solar-system-data.ts` 保存原始 Horizons 数字、查询条件、历元和来源。
- `solar-system-physical-profiles.ts` 保存碰撞模型、材料层、刚体惯性因子和 J2000 自转角动量。
- `center-of-mass.ts` 使用补偿求和计算质量加权位置和速度，减少大质量与大距离乘积相加时的浮点损失。
- `solar-system.ts` 负责单位转换、质量计算、物理资料深拷贝、质心化和返回全新对象。

### 目录与选择

目录行使用稳定的 `aria-label="聚焦天体名"`。全景中定位环按“选中天体、主恒星、目录顺序”处理重叠，中心距离小于 18 像素时只保留优先项。画布点击在当前可见定位点中选择距离指针最近且不超过 20 像素的天体，结果不会再受三维深度顺序影响。

定位环避让只影响画布上的显示和点击。目录始终列出当前模拟中的全部天体，隐藏定位环对应的天体仍可从目录查看并聚焦，因此目录是完整访问入口。

`?markerDiagnostics=1` 是只读验收模式。启用后，canvas 的 `data-visible-body-markers` 会暴露当前真实可见定位点的 CSS 像素坐标，`data-camera-state` 会暴露全景或聚焦模式、相机位置和控制中心。两份数据最多每 100 毫秒更新一次，供浏览器测试证明定位环可见、点击有效且相机真实移动。普通访问不生成这些序列化数据。

### 画面资产映射

- `sun` 到 `neptune` 的 10 个固定 ID 各自映射一个颜色表面。
- `saturn` 额外映射透明度环，使用 `1.24R..2.27R` 半径和 `26.73°` 轴倾角。
- 用户创建的稳定 ID、陌生导入 ID 和资产失败状态继续使用程序化表面，目录与选择入口保持完整。
- 金星资产表示雷达增强地表；木星、土星、天王星和海王星表示固定时间片或合成外观。界面不会把它们描述成实时天气。

## 验证

- 纯函数测试覆盖 10 个星历 ID 与物理资料 ID 的双向完整映射、SI 换算、材料顺序与总和、惯性边界、自转有限性、质心残差、相对状态不变和嵌套资料独立对象。
- REBOUND 集成测试推进一儒略年，断言 10 体状态有限，能量和角动量向量相对漂移不超过 `1e-10`；每个父子轨道的相对距离保持在初始值的 `0.45..2.2`，并保持引力束缚。
- 目录和轨道测试覆盖元数据完整、父级存在、月球围绕地球和未知天体回退。
- 浏览器验收覆盖 10 个中文名称、海王星聚焦、返回全景、实时画布定位点点击、手机滚动目录和 WebGL2 回退。
- M1 收口记录默认 10 体的生产构建、两秒性能和完整测试矩阵，详见 `docs/2026-07-15-stary-m1-acceptance.md`。
- M2 Task 2 单元测试覆盖 10 个固定 ID 的表面映射、土星环比例和未知 ID 程序化回退；Playwright 证明地球和土星在桌面与手机 WebGL2 真实画布中可见。

当前可用模板只有 JPL J2000 太阳系。空白、双星和随机系统只保留模板边界，尚未提供场景选择入口。当前牛顿 10 体模型省略其他卫星、小行星和相对论项，长期结果不承诺逐点复现完整 Horizons 星历。画面资产也只覆盖这 10 个固定 ID；新增天体使用程序化回退。
