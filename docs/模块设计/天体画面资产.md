# 天体画面资产

## 当前状态

M2 Task 2 已完成首批真实天体资产。太阳、八大行星和月球拥有本地表面颜色图，土星额外拥有实体环透明度图。运行时按观察需要加载资源，失败时保留程序化外观。

## 设计

### 职责与结构

- `public/assets/planetary/` 保存浏览器直接读取的 11 个成品。
- `planetary-assets.json` 保存发布者、许可、处理方法、原图和成品 SHA-256。
- `texture-asset-manifest.ts` 在模块加载时用 Zod 校验清单结构、URL、尺寸、字节、哈希和唯一性。
- `body-asset-plan.ts` 把固定天体 ID 映射到表面与可选行星环。
- `browser-texture-loader.ts` 负责请求、MIME 检查、ImageBitmap 解码和 Three Texture 配置。
- `texture-cache.ts` 负责场景级共享、引用计数、取消、失败淘汰和销毁。
- `body-visual-assets.ts` 把纹理租约绑定到正式天体材质，并维护只读诊断状态。
- `planetary-ring.ts` 创建土星环几何、径向 UV 和程序化透明度回退。

物理层不读取这些文件。贴图、环和回退只改变画面，天体质量、半径、位置、速度和积分结果继续来自 `BodyState`。

### 来源、许可与处理

统一来源为 `https://www.solarsystemscope.com/textures/`，作者与署名为 Solar System Scope / INOVE，许可为 CC BY 4.0。上游说明贴图基于 NASA 高程和影像数据，并参考多个探测器与望远镜观测调色；部分未测绘缺口使用匹配地形补全。

颜色原图为 `2048×1024 JPEG`。本项目使用 Pillow 12.2.0 和 Lanczos 缩到 `1024×512`，再以 WebP 质量 82、method 6 编码。土星环原图为 `2048×125 PNG`，缩到 `1024×63 PNG` 并保留通道。11 个成品合计 `550,977` 字节。

成品需保留 Solar System Scope / INOVE 署名、CC BY 4.0 链接和处理说明。NASA 数据基础不会改变成品许可归属。金星图表示雷达增强地表；气态与冰巨星图表示固定时间片或合成外观。

### 加载与缓存

固定天体成为焦点或投影半径达到 medium LOD 时才启动加载。每个场景拥有一个 `TextureAssetCache`：

1. 同一资产的并发请求合并成一个底层加载。
2. 每个等待者可以单独取消；仍有其他等待者时底层请求继续。
3. 没有等待者和租约时取消底层请求，迟到资源立即释放。
4. 成功资源通过租约计数；最后一个租约释放时关闭 ImageBitmap 并释放 Texture。
5. 失败条目立即移出缓存，新的缓存请求可以重新加载。
6. 场景销毁会取消待决请求、释放全部就绪资源并拒绝新请求。

BodyVisual 的单次绑定启动后保持稳定。某项失败会进入 `fallback`，当前场景不会持续重试本地缺失文件；页面或场景重建会建立新缓存并重新加载。这个策略避免永久 404 或损坏图片产生请求循环。

### 表面与回退

表面颜色图使用 sRGB，水平重复、垂直夹紧和线性 mipmap。图片解码时执行垂直翻转，与 Three.js 球体 UV 对齐。真实贴图绑定后材质底色切到白色，防止目录颜色再次染色。

动态创建天体、未知 ID 和失败资产继续使用外观模块给出的程序化材质。天体 mesh、定位环、目录和聚焦能力都不会因纹理失败被移除。

### 土星环

土星环使用真实半径比例 `1.24R..2.27R` 和 `26.73°` 轴倾角。RingGeometry 的 U 坐标按实际半径重新计算，透明度图沿径向展开，V 固定在纹理中线。WebGPU 使用 256 个径向分段，WebGL2 使用 160 个。

环资产尚未就绪或失败时使用小型 DataTexture 生成条带与卡西尼缝近似。实体环挂在土星 root 下，随球体使用相同真实半径缩放；青色选择定位环继续作为独立 `markerRing`，两者不会共用资源或诊断名称。

### 构建与诊断

`scripts/verify-build.mjs` 检查清单数量、成品路径、字节和 SHA-256。任何文件缺失、被替换或压缩参数漂移都会让生产构建失败。

`visualDiagnostics=1` 增加四组证据：

- `visualSurfaceResources`：表面资产 ID、状态和材质绑定结果。
- `visualPlanetaryRingResources`：环资产、比例、状态和可见性。
- `visualPlanetaryRingProjections`：环中心、两条屏幕基向量和内半径比例。
- `visualResourceCounts`：行星环 mesh 数和纹理缓存快照。

普通访问不会序列化这些诊断。它们只服务自动化验收和排障。

## 实现细节

加载状态包含 `procedural`、`idle`、`loading`、`ready` 和 `fallback`。表面与环分别维护状态与租约，因此一个资源失败不会撤销另一个已经成功的资源。LOD 替换只操作 SphereGeometry，材质与纹理租约保持原对象。

释放顺序为绑定取消与租约释放、天体 geometry/material/程序化纹理释放、场景缓存兜底释放、renderer 释放。`dispose()` 和租约 `release()` 都支持重复调用。加载代次通过缓存 entry 身份隔离，已经从 Map 移除的旧请求完成后只能释放结果，无法进入新 entry。

## 验证

- 单元测试覆盖清单校验、10 个固定天体映射、未知 ID、浏览器 HTTP/MIME 检查、颜色空间、垂直翻转、ImageBitmap 释放和土星环 UV。
- 缓存测试覆盖共享请求、部分取消、全体取消、失败后重试、就绪销毁、待决销毁、迟到资源和幂等租约。
- BodyVisual 测试覆盖土星表面与环绑定、LOD 保持租约、加载期间删除和迟到纹理不回挂。
- Playwright 在桌面默认后端与手机强制 WebGL2 下验证地球海陆纹理、土星左右环带、内洞和径向明暗；错误 MIME 流程验证地球回退仍可选择、聚焦和显示。
- 完整门禁通过 39 个 Vitest 文件、291 项测试和 18 条 Playwright 流程。
- 当前生产资产总计 `550,977` 字节；生产包为 `2,521,163` 原始字节、`1,117,354` gzip 字节。
